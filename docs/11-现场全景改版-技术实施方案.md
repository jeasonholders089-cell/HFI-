## 一、总体架构与关键决策

### 1.1 决策一：坐标表放服务端，不进客户端 bundle

| 方案 | 代价 | 结论 |
| --- | --- | --- |
| 客户端（照 `colleges-data.ts` 的样子打进 bundle） | 2468 行 ≈ 170KB 源码，**大屏首屏白扛** | ❌ |
| **服务端：在 `/api/children/summary` 里完成名字→坐标的匹配** | 服务端 bundle 变大（不进浏览器，无所谓） | ✅ |

**可证伪的检查**：构建后客户端 chunk 里**不允许**出现只在坐标表里存在的字符串
（用 `Cambridge College of Healthcare & Technology` 当探针，见 §6.3 第 10 条）。

### 1.2 决策二：三张表职责不重叠，同一学校以 113 表为准

| 表 | 内容 | 谁用 | 放哪 |
| --- | --- | --- | --- |
| `data/colleges.csv` → `lib/colleges-data.ts` | 113 所 × 46 列**事实字段** | 选校地图 | 客户端（已有） |
| `data/university-coords.csv` → `lib/university-coords.ts` | 2468 所，**只有名字 / 城市 / 州 / 坐标** | 现场全景的梦想院校地图 | **服务端** |
| `lib/university-names.ts` | 中英文别名（人工维护，现 69 条） | 两处共用 | 服务端（改完不再进客户端） |

**v1.1 更正**：原文写「同一所学校两边都有（例：斯坦福）时，先用 113 表」。
这条规则**从 v1.0 起就没有被实现**，实测后**作废**（见 §0 更正 11）：
同一所学校两份表的坐标差投影后 ≤ 0.16px，远小于肉眼可辨的量级，
而把 113 表引到服务端要多背一份 46 列数据的解析成本。
现在的实际口径就是最终口径：**梦想院校地图一律用坐标表**（`lib/university-coords.ts`），
113 表只服务 `/colleges`，两张表在坐标上互不依赖。

### 1.3 决策三：投影与底图抽成共享件，不复制

| 抽什么 | 从 | 到 | 兼容做法 |
| --- | --- | --- | --- |
| `project()` / `MAP_W` / `MAP_H` / `MAP_VIEWBOX` | `lib/colleges-project.ts` | `lib/map-project.ts` | 原文件 **re-export**，现有 import 与 8 个测试文件零改动 |
| 底图三层（海洋 / 邻国 / 美国 + AK/HI 插图） | `components/colleges/colleges-map.tsx` 内联 | `components/map/us-base-layers.tsx` | 选校地图改为引用，**行为与 DOM 结构不变**（现有地图测试必须继续通过） |

### 1.4 决策四：匹配三级 + 唯一性闸，命中不唯一就是没命中

名字 → 坐标的匹配是本次最容易出错的地方。规则（详见 §3.3）：

```
① 别名表（我们的 69 条中文名 + 每条自带的英文别名）
② 精确匹配（归一化后与机构名完全相同）
③ 唯一包含匹配（互相包含，且**只命中一所**）
④ 人工覆盖表
—— 任何一级命中超过 1 条 → 一律视为「未命中」，宁可不上图，也不打错点
```

> **为什么不做模糊匹配降级**：宁可少一个点，也不要在大屏上把「华盛顿大学」标到 Bothell 去。
> 未命中的学校不会消失——它进名单，并在图下计入「另有 N 人次填了暂未收录的院校（M 所）」。

### 1.5 决策五：地图只显示人数，不显示姓名

大屏是公开页面，`AGENTS.md` 第五节禁止「孩子姓名 + 个人画像」的组合，「谁选了哪所学校」正是那个组合。
接口与组件都不传、不渲染姓名（`/api/children/summary` 的 `children` 字段脱敏仍按一期决定不做）。

### 1.6 决策六：分类改 8 类后，老数据不做静默迁移

`categorized()` 保持严格校验；旧 4 类的记录变成「待分类」，走页面上已有的
「AI 补全分类」按钮（对应 `/api/children/analyze` 里「只重分类、不重生成方向」的分支）。
**不写自动映射**（旧「自然科学」里既有物理也有 CS，机械映射会把 CS 永久钉在自然科学里）。

### 1.7 分类字符串的冻结值（**四个地方必须逐字一致**）

这 8 个字符串会**存进数据库**（`children.ai_directions` 的 `category`）、写进 **AI prompt**、
渲染成**大屏标签**，还决定统计的分桶。所以它们不是文案，是**数据契约**，在这里冻结：

```ts
export const CATEGORIES = [
  "人文科学", "社会科学", "商科与管理", "自然科学",
  "数学与计算", "工程与应用", "艺术与设计", "健康与公共服务",
] as const;
```

| 同步点 | 位置 |
| --- | --- |
| 代码 | `lib/growth-categories.ts` |
| AI prompt（**三处**：家长自助填写的初次分析 / 现场「开始分析」/ 「只重分类」） | `app/api/children/route.ts`（初次）· `app/api/children/analyze/route.ts`（另两处）——都从 `CATEGORY_ENUM` / `CATEGORY_RULES` 派生，不各写一份 |
| 产品方案的定义与判定规则 | `docs/10` §2.1 / §2.2 |
| 项目规范的分类体系 | `AGENTS.md` §6 |

**顺序也冻结**：`summary` 接口按这个顺序初始化计数，条形图在人数相同时按这个顺序排——
顺序变了，大屏上并列的两条会互换位置。测试 C-1 用写死的期望数组逐字比对，就是为了逼着四处一起改。

---

> **v1.1**：8 个字符串**不变**，改的是 `CATEGORY_RULES` 里的**传媒**一条（§0 更正 12）——

### 2.3 `data/university-coords.overrides.json`（新）

```json
[
  {
    "match": "帕森斯设计学院",
    "name_en": "The New School",
    "reason": "帕森斯是 The New School 下辖的设计学院，Scorecard 无独立机构记录；The New School 的坐标即帕森斯所在",
    "source": "https://www.newschool.edu/about/"
  }
]
```

- 键是**别名表的规范中文名**（匹配管线第 ① 级的上游产物）。
- 值给 `name_en`，**坐标由构建脚本去 `data/university-coords.csv` 里解析**——不手抄经纬度，避免手抖。
- `name_en` 在坐标表里找不到、或命中不唯一 → **构建失败**（退出码 1），不允许静默跳过。
- 每条必须带 `reason` 与 `source`。

### 2.4 两个脚本

| 脚本 | 输入 | 输出 | 性质 |
| --- | --- | --- | --- |
| `scripts/extract-university-coords.ts` | Scorecard 解压后的 `Most-Recent-Cohorts-Institution.csv` | `data/university-coords.csv` | **一次性**，保留以求可追溯；不进 `build:data` |
| `scripts/build-coords.ts` | 上面那份 CSV + overrides | `src/lib/university-coords.ts` | 日常构建，幂等 |

`extract` 用 `readline` 流式读（95MB / 3308 列，整段读进字符串会爆内存）；
CSV 解压后放在 `tmp/`（gitignore），脚本找不到时打印三条命令（下载 / 解压 / 重跑），
**不自己下载**（网络与解压工具交给环境，脚本只管数据）。

### 2.5 产物格式 `src/lib/university-coords.ts`

```ts
// 本文件由 scripts/build-coords.ts 生成，请勿手改。
export const COORD_SOURCE = { url: "…", version: "2026-06-10", count: 2468 };
/** [name_en, city, st, lat, lng] —— 元组形式是为了压体积（2468 行，约 170KB） */
export type CoordRow = readonly [string, string, string, number, number];
export const COORD_ROWS: CoordRow[] = [ ["Brown University","Providence","RI",41.8262,-71.4025], … ];
```

**为什么提交产物**：Docker 构建上下文是 `src/`（`compose.yaml` 的 `build: .`），

### 3.2 `lib/dream-schools.ts`（新，纯函数）

**人次口径**（与页面上「梦想院校统计」现在的口径保持一致，不改）：先用 `parseUniversities()`
拆词与归一，`Set` 去重 → **同一个孩子在同一个学校只计 1 次**；不同孩子累加。

> **v1.1 量词（评审 M4）**：这个数字是**人**（"填了这所学校的孩子数"），**不是人次**——
> 真正的人次是**跨校求和**（同一个孩子填 3 所就被算 3 次，只用于图下那行小字）。
> 现在的实现把两者用反了：地图副标题与图下小字写「人次」，而它们说的其实是人。
>
> 文案分工（写死在组件里，别再混）：
> 单所院校一律「**N 人**」（地图标签、`<title>` 悬停、完整名单）；
> 跨校合计一律「**N 人次**」并补半句「同一孩子的多所院校各计一次」（图下小字、地图副标题的口径说明）。
> **验收**：全页 grep `人次`，只允许出现在这两处。

### 3.3 归一化与唯一性闸（本方案最容易出错的地方，写死）

`normalizeName` **只做四件事**：

1. `NFKC` 归一（全角→半角）；
2. 转小写；
3. 去掉空格与标点：`.,·’'“”"-–—()（）&`；
4. 去掉结尾的 `main`（`Pratt Institute-Main` → `Pratt Institute`）。

**刻意不做的三件事**，以及理由：

| 不做 | 为什么 |
| --- | --- |
| 不去 `The` 前缀 | 索引与查询必须同规则；去掉就要两边都去，而 `The New School` 与 `New School` 是否同一所没有把握，宁可不做 |
| 不去 `University` / `College` 后缀 | 会造成误合并（`Boston University` vs `Boston College` 是两所学校） |
| 不做词序调整 / 缩写扩展 | 收益小、误伤大；这些靠别名表人工维护 |

**唯一性闸**：

- 索引构建时，归一化后同名的机构**整组不进索引**（实测 15 组，如三个州的 `Lincoln University`）；
- 查询时，第 ③ 级「互相包含」若命中 ≥ 2 条，同样判为未命中。

举例（都会写进单测）：

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| `Pratt Institute` | ✅ 命中 `Pratt Institute-Main` | 去 `-Main` 后精确唯一 |
| `University of Washington` | ✅ 命中主校区 | 主校区在源数据里叫 `University of Washington-Seattle Campus`，精确匹配命不中；靠**唯一包含**命中（`-Bothell` / `-Tacoma` 是 `MAIN=0`，已过滤） |
| `Lincoln University` | ⛔ 未命中 | 三个州各一所，无法判断 |
| `帕森斯设计学院` | ✅ 命中 `The New School` | 人工覆盖表 |
| `麻省理工` / `MIT` | ✅ 命中 | 别名表 |

> 「精确先于包含」这个顺序仍然有意义：`Hampshire College`、`Georgia Institute of Technology Main Campus`
> 这类源数据里就有的写法，走第 ② 级精确匹配，不会被第 ③ 级的歧义闸误伤。

## 五、交互的技术策略

| 项 | 规则 |
| --- | --- |
| 视口 | 恒定 `0 0 975 610`，**不做缩放平移**（大屏是「一眼看完」，不是「逛地图」） |
| 气泡半径 | `r = min(15, 4.5 + 3.2 × sqrt(count))`。1 人 ≈ 7.7、4 人 ≈ 10.9、9 人 ≈ 14.1、16 人以上封顶 15 |
| 气泡颜色 | 单一色 `--dot-lac`（砖红），与选校地图的「文理学院」同色但**不在同一页**，不产生歧义 |
| 气泡描边 | `--map-land`，宽度随 `1/k^0.82` 补偿（复用选校地图的公式，k=1） |
| 标签 | 人数前 **12** 名挂「校名 · N 人」（v1.1：名额从 8 提到 12、**补上单位**）；复用 `lib/colleges-labels.ts` 的 `layoutLabels`（5 个偏移位 + 冲突就放弃） |
| 字体 | 标签字号 11，不随人数变（大小已经由气泡表达了） |
| 悬停 | SVG `<title>`：`校名 · N 人`。零 JS、零状态。**v1.1：必须删掉 `<circle>` 上的 `pointerEvents="none"`**（它让元素不参与 hit-test，原生 `<title>` 根本不触发；那是从选校地图照搬来的属性，本页没有平移拾取，不需要它）。同时清掉没人读的 `data-school` / `data-count` |
| 点击 | 无（不打开详情、不跳转），避免大屏被误触带走 |
| 响应式 | 高度改为 `min(52vh, 520px)`（v1.1）；容器宽度 < 640px 时降到 `42vh`，避免手机上占满整屏 |

**不做清单**（复述 `docs/10` §3.2，防止实现时顺手多写）：不做缩放、平移、双击；
不做筛选、搜索、洞察榜、对比位、详情栏、表格视图；不做点击跳转。

**v1.1 改写（评审 M2）**：不再写「本页唯一的交互是悬停看人次」——**大屏前面没有鼠标**，
而本页又不做缩放平移，所以悬停只可能是工作人员在笔记本上预览时的加分项。
信息的承载者必须是**标签**（前 12 名挂「校名 · N 人」）与 **④ 完整名单**；
悬停只是锦上添花，且必须真的能用（删 `pointerEvents="none"` 后才有 `<title>`）。
**验收口径**：在**不悬停、不点击**的前提下，看大屏的人能说出人数最多的 3 所学校与名次。

**关于「点位散开」**：`docs/10` 的风险表里写了「沿用选校地图已有的散开 + 标签避让」。
这里要说清楚——**散开在本页不会触发**：`spreadPoints` 的启动条件是 `k ≥ 2.5`，
而现场全景恒定 `k = 1`（不做缩放）。所以本页只用**标签避让**，气泡重叠靠**半径差异**区分
（1 人 7.7px、9 人 14.1px，差一倍以上，肉眼可辨）。
如果活动当天发现小样本下点太挤，再单独评估要不要降低散开阈值——不在本期范围。

### 5.1 现场态：轮询与降级（**v1.1 新增，评审 M1**）

**问题**：现在这一页只在挂载时读一次数据（`app/explore/page.tsx` 的 `useEffect(..., [])`），
全仓库 grep `setInterval` / `EventSource` / `WebSocket` / `revalidate` → **0 命中**。
家长在 `/register` 提交的新问卷不会出现在大屏上，要工作人员手动点「刷新数据」。
它**静默地报旧数字**——比报错更伤信任。

| 项 | 规则 |
| --- | --- |
| 周期 | **30–60 秒**拉一次 `/api/children/summary`（沿用已有的 `cache: "no-store"` 与 15s `AbortController` 超时） |
| 跳过条件 | `running`（AI 分析中）/ `showClear`（弹窗打开）/ `deletingId` 非空时**跳过这一轮**，不打断正在发生的动作 |
| 失败降级 | 后台轮询失败**不清空数据、不写 `error`、不弹红字**；保留最后一次成功的数据。连续失败 3 次才在标题行显示「数据可能已过期 · 最后更新 HH:MM」 |
| 成功标记 | 每轮成功更新标题行的**「更新于 HH:MM」**——现场判断"大屏是不是活的"的唯一证据 |
| 与 `loading` 的关系 | 后台轮询**不允许**翻转 `loading`：现在的 `refresh()` 会 `setLoading(true)`，它驱动「刷新数据」的按钮文案（"读取中…"）与三个按钮的禁用态——轮询直接调它，大屏会每 60 秒闪一次、并把工作人员手里的按钮锁住。轮询走单独的静默路径（`silentRefresh()`），只有人点「刷新数据」时才走带 loading 的那条 |
| 组件卸载 | `clearInterval`，避免在 `/explore` 与 `/colleges` 之间来回切时堆定时器 |
| 不在范围 | 不做 WebSocket / SSE（现场网络不稳，长连接断了要重连与补偿，复杂度远高于收益）；不做"有新数据时弹提示"（大屏没人点它） |

**可证伪的验收**（`docs/11` §6.3 第 16 条）：插入一条新记录 → **不碰任何按钮** → 60 秒内大屏总数 +1。
`docs/11` §6.2 的页面测试里用假定时器覆盖"跳过条件"与"失败不清空"两条。
