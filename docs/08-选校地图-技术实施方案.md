## 二、总体架构与关键决策

### 2.1 决策一：不新增后端接口

`/colleges` 是**纯静态页面 + 客户端计算**，不新增任何 API 路由：

| 能力 | 数据来源 | 需要接口 |
| --- | --- | --- |
| 113 所院校数据 | 构建期编译进 bundle | 否 |
| 地图底图 | 构建期投影好的静态 SVG 路径 | 否 |
| 筛选 / 搜索 / 排序 / 洞察榜 | 客户端对内存数组做纯函数计算 | 否 |
| 黑马匹配分档 | 客户端纯函数 | 否 |
| 收藏 / 对比位 / 黑马分数 | `localStorage` | 否 |
| 埋点 | 一期不做（`docs/05` 第十节） | 否 |

**整页零网络请求。** 与 `AGENTS.md`「地图必须零外部依赖」同向，也是现场弱网的验收点。
代价是 `/colleges` 的 chunk 变大——靠路由级代码分割保证它不影响首页与大屏。

### 2.2 决策二：三层数据，职责不重叠

这是「前后字段一致」的结构基础——**同一份数据只在一层里被定义一次**：

```
第①层  源（不进版本库）    tmp/cmc_data.json（解密产物，一次性）

第②层  契约与数据（进版本库，人工可改）
          lib/colleges-schema.ts      ← 字段契约，唯一真源
          data/colleges.csv           ← 事实字段
          data/us-states.topo.json    ← 底图源（人口普查局公开数据）

第③层  构建产物（进版本库，禁止手改）
          lib/colleges-data.ts        ← 解析 + 派生 + 投影后的类型化数组
          lib/us-map-paths.ts         ← 州界 SVG path
```

产物也进版本库的理由：**现场构建不依赖网络与外部数据源**。代价是产物可能与源不同步——
用 7.2 的「产物一致性」测试兜住（`pnpm build:data && git diff --exit-code lib/`）。

### 2.3 决策三：计算与展示分离

字段分两类，**这是避免运行时正则与字符串拼接的关键**：

| 类 | 例子 | 存哪 | 谁用 |
| --- | --- | --- | --- |
| **展示原文** | `4.4%` / `$68,454(26-27)` / `11月1日(SCEA)` | CSV 原样 | 渲染 |
| **派生数值** | `accNum=4.4` / `tuitionNum=68454` / `ddlNum=1101` / `satLo=1490` | 构建期算出，写进产物 | 排序、对比、高亮、分档、筛选 |

原则：**运行时不解析字符串**。所有正则与容错都发生在构建期，且有测试断言覆盖率。
收益是排序、对比高亮、黑马匹配三处逻辑都退化成纯数值比较，不会因为一个空格或括号崩掉。

### 2.4 与现有代码的关系

| 项 | 处理 |
| --- | --- |
| 现有三个页面 | 业务逻辑不动，只把各自的 header 换成共享导航组件 |
| 共享导航 | 新建 `components/site-nav.tsx`，顺手修两个坏锚点（`#about` 不存在、`工作人员入口` 指向 AI 试用区块） |
| `lib/university-names.ts` | 不复用。它是 40 条手写别名表；`/colleges` 用数据自带的 `ab` 字段 |
| 数据库 | **不涉及**。院校数据不进库（一期不建院校库），不改 `db/schema.ts`，无新迁移 |

### 3.3 派生字段契约（构建期计算，写进产物）

这一节是「运行时不解析字符串」的落点。**每个派生字段都必须有单元测试。**

| 派生字段 | 由什么算 | 谁用 |
| --- | --- | --- |
| `x` `y` | `project(lat, lng)` | 打点 |
| `accNum` `erNum` `rrNum` `trNum` `intlNum` `gpaNum` | 取首个数字，转不出则 `null` | 排序、对比高亮、洞察榜 |
| `satLo` `satHi` | `sat` 匹配两位到四位数的区间；不匹配则 `null` | 分档、排序 |
| `tuitionNum` | 去掉 `$` 和 `,` 后取数；**大于 1000 才算有效**（源码的保护条件） | 排序、对比高亮 |
| `ddlNum` | 从 `ea`（无则 `rdd`）取月/日，按「8 月为学年起点」归一成 `月*100+日` | 排序 |
| `lever` | `erNum > 0 且 rrNum > 0 时 erNum / rrNum，否则 null` | 详情 6 节、对比表、**洞察榜（C1 更正）** |
| `typeKey` | `lac` / `pub` / `uni` | 颜色与徽标（`pub` 只对 `uni` 生效） |
| `roundsArr` | 按竖线拆分 | 筛选、徽标 |
| `singleRound` | `roundsArr` 全为 `RD` | 详情 5 / 6 节的文案回退 |
| `hasEarly` `hasED` `hasREA` | 由 `roundsArr` 派生 | 第 15 节数据信号、收藏健康度 |
| `searchIndex` | `en`（小写）、`zh`、`ab`、`city`（小写）、`st`（小写） | 搜索，见 6.7 |

> `lever` 用派生数值而不是渲染时现算，是因为它有**三个消费方**（详情卡、对比表、洞察榜）。
> 一处算错三处一起错；放构建期加一个单元测试，比散在三处强。

### 3.6 空值约定

- 数据层统一 `null`，**不用空字符串也不用 `undefined`**——要能区分「空字符串」和「真的没有」；
- 展示统一过 `formatField(value, kind)`：

| kind | 空值渲染 |
| --- | --- |
| `text` / `percent` / `money` / `count` | 未公布 |
| `rank` | 未上榜 |
| `list`（标签、批次） | — |
| `date` | 以官网为准 |

**禁止在 JSX 里写 `value || '未公布'`**——`chg = 0`（排名持平）会被误判成空。
这是本项目最容易出的一类 bug，7.2 里有一条专门测它。

### 3.7 从源 JSON 到 CSV 的一次性提取

```

       data/__fixtures__/reference-xy.json（113 条 en 到 {x,y}，供投影回归）
```

### 4.5 底图的三层结构（2026-09-17 补）

第一版底图只有「容器底色 + 49 条州界」，美国以外的区域是空的 —— 陆地与海洋糊成
一整块，邻国看不见，阿拉斯加完全没有画。参考实现的做法是分三层，我们沿用同一套分层、
但换成自己的配色：

| 层 | 内容 | 画法 |
| --- | --- | --- |
| ① 海洋 | 整块矩形（975 × 610） | **单一颜色** `--map-ocean`（与容器底色同一个值） |
| ② 邻国陆地 | 加拿大 / 墨西哥 / 巴哈马 / 古巴 | 平涂 `--map-neighbor`，白描边，**不透明** |
| ③ 美国 | 49 条州界 + AK / HI 插图 | 填充 `--map-land`，**整组加 `drop-shadow`** —— 这是把它从邻国陆地上「抬起来」的唯一一层级信号 |

**三层的色阶是刻意的**：海洋 `#e8e6dc`（最深）→ 邻国 `#efece3`（中间）
→ 美国 `#fdfcf8` + 阴影（最亮）。全部取自本产品色板，**没有引入蓝色或任何新色相** ——
参考实现那套蓝绿海洋是 CMC 的视觉语言，不照搬。

**海洋为什么不做渐变**：SVG 默认的 `preserveAspectRatio="xMidYMid meet"` 是
「等比缩放 + 居中」，元素盒子的宽高比一旦与 viewBox(975:610) 不一致，左右或上下就会
留白。渐变会在「内容区」与「留白区」之间露出一条竖直接缝（用户第一轮反馈里的红框就是它）。
纯色 + 与容器同色，接缝就不存在了。见 [4.6](#46-svg-的留白坐标换算必须扣掉它2026-09-17-补)。

### 4.6 SVG 的留白：坐标换算必须扣掉它（2026-09-17 补）

**这是"有些学校点不中"的根因，写成硬规矩。**

`<svg className="h-full w-full">` 会拉出一个与 viewBox 宽高比不同的盒子，`meet` 之下
SVG 内容等比缩放后居中，四周（这里是最常见的左右两侧）留白。**留白区不属于 viewBox**，
所以任何「屏幕坐标 → viewBox 坐标」的换算都必须用**内容区**，不能用 `getBoundingClientRect()`。

```
scale      = min(rect.width / vb.w, rect.height / vb.h)
内容区宽高 = vb.w * scale, vb.h * scale
内容区左上 = rect.left + (rect.width - 内容区宽)/2, rect.top + (rect.height - 内容区高)/2
```

用错会怎样（实测值）：宽 940 / 高 522 的容器，scale = 0.8557，左右各留白 52.9px，
坐标误差 = `|54.9 − 0.1125x|`。取 15px 的拾取阈值（≈15.6 viewBox 单位）反推：
**x < 349 与 x > 626 的点全部点不中** —— 也就是西海岸与东海岸全军覆没，
只有大平原那一条（几乎没有学校）能点。同一个偏移也影响悬停、滚轮缩放锚点与拖拽增量。

现在地图里所有换算都走 `mapRect()`（`components/colleges/colleges-map.tsx`），
另有单测把元素盒子的宽高比刻意设成 1200:500（留白 200px）来守这条：
`components/colleges/__tests__/colleges-map.test.tsx` 的「靠左边缘的院校也点得中」。

**AK / HI 的插图区摆放**（`scripts/build-us-map.ts` 的 `INSET_TRANSFORM`）：

| 州 | 源 bbox | 变换 | 变换后 bbox |
| --- | --- | --- | --- |
| AK | `[-57,464]..[202,604]` | `translate(57,63) scale(0.86)` | `[8,462]..[231,582]` |
| HI | `[216,528]..[332,603]` | `translate(20,0)` | `[236,528]..[352,603]` |

两处都相对参考实现做了修正：**参考实现里阿拉斯加左边被画布裁掉了**（min x = -57），
我们右移让它完整可见；夏威夷再右移 20 避开阿拉斯加。这两条都有构建期断言 + 单测守。
`lib/us-map-labels.ts` 里 AK / HI 的标签锚点跟着同一组位移走，保证文字落在形状中心。

### 5.2 状态模型（单一 reducer）

组件之间不传回调，全部走一个 `useReducer`：

```ts
type State = {
  view: 'map' | 'table';
  q: string;
  filters: { type; region; round; test; rank; match };
  insight: InsightKey | null;      // 单值：同时只能开一个（源码行为）
  favOnly: boolean;
  viewBox: { x: number; y: number; w: number; h: number };
  hovered: string | null;          // 存 en
  browsing: string | null;         // 浏览位当前院校 en
  slots: string[];                 // 对比位，最多 3，有序
  compareOpen: boolean;            // 对比浮窗
  profileOpen: boolean;            // 全屏档案浮窗
  userSat: number | null;          // 黑马匹配
  fontLevel: 0 | 1 | 2;            // 字号三档
  lang: 'zh' | 'en';
};
```

派生数据一律 `useMemo`：`filtered`、`matchTags`、`searchHits`、`insightCounts`。
**不把派生数据放进 state**——那是不同步的根源。

### 5.3 对比位状态机与不变量

| 事件 | 前置 | 迁移 |
| --- | --- | --- |
| `ADD_SLOT(en)` | `slots.length < 3` 且 `en` 不在 slots 中 | 追加到末尾 |
| `REMOVE_SLOT(en)` | `en` 在 slots 中 | 移除；若剩余不足 2 所则关闭对比浮窗 |
| `CLEAR_SLOTS` | — | 清空；关闭对比浮窗 |
| `BROWSE(en)` | — | 只改 `browsing`；**`slots` 不变** |

不变量（开发模式用 `console.assert` 守）：

1. `slots.length <= 3`；
2. `slots` 内无重复；
3. `slots` 里每个 `en` 都能在 `COLLEGES` 找到；
4. `browsing === null` 时浏览位渲染空态，不报错；
5. `slots.length < 2` 时 `compareOpen === false`。

> **`BROWSE` 不动 `slots`，是「浏览与收集分离」这条产品逻辑在实现层的唯一落点。**
> 组件测试必须专门覆盖（7.3 第 3 行）。

### 5.4 组件职责边界

| 组件 | 拥有 | 不拥有 |
| --- | --- | --- |
| `colleges-toolbar` | 分发筛选 / 搜索 / 洞察榜 / 黑马事件 | 不自己过滤 |

### 6.2 最近点拾取

```ts
// 屏幕坐标 → viewBox 坐标
const px = vb.x + (clientX - rect.left) / rect.width  * vb.w;
const py = vb.y + (clientY - rect.top)  / rect.height * vb.h;

// 阈值：15 屏幕像素换算成 viewBox 单位，且不小于 6
const thr = Math.max(15 * (vb.w / rect.width), 6);

// 在「当前过滤结果」里找最近的，不是全量——被筛掉的院校点不能被选中
let best = null, bd = Infinity;
for (const s of filtered) {
  const d = Math.hypot(s.x - px, s.y - py);
  if (d < bd) { bd = d; best = s; }
}
return best && bd <= thr ? best : null;
```

东北部 57 所挤在一起，没有这条就点不中。**阈值用屏幕像素而不是 viewBox 单位**，
保证放大缩小时手感一致。

### 6.3 缩放与平移

| 项 | 规则 |
| --- | --- |
| 滚轮缩放 | `f = 1.0016 ** (-deltaY)`，`{ passive: false }` 并 `preventDefault` |
| 双击 | `f = 1.8` |
| 缩放锚点 | 光标位置保持不动：`x = cx - (cx - x) / f`，`y = cy - (cy - y) / f` |
| 宽度边界 | `w ∈ [110, 975]`，`h = w * 610 / 975`（等比，不拉伸） |
| 位置边界 | `x ∈ [0, 975 - w]`，`y ∈ [0, 610 - h]` |
| 触屏 | `pointerdown/move` 记录多指距离做捏合；单指平移 |

**必须处理的两个坑**：

1. **拖拽结束后不能触发点选**。参考实现用一个 `wasDrag` 标记，在 `pointerup` 后抑制
   紧随其后的 `click`；表格里也有同样的 `_tblDrag` 机制。两处都要做，否则「拖地图时松手
   正好压在一个点上」会误开详情。
2. **地图区域内滚轮不滚页面**。参考实现有一句常驻提示「鼠标置于地图区域时无法滚动页面」。
   我们的处理：桌面端保留 `preventDefault`，但在地图下方给一行静态提示；
   移动端不做 `touch-action` 拦截，保证页面能正常上下滑。

### 6.11 黑马匹配

**分档算法**（去掉全部话术，只留计算，与源码逐行一致）：

```ts
function matchTag(college, userSat) {
  if (userSat == null) return null;
  const acc = college.accNum;
  const band = (college.satLo != null && college.satHi != null)
             ? [college.satLo, college.satHi] : null;
  if (!band) return (!isNaN(acc) && acc < 15) ? 'r' : 'h';   // 不看标化：看综合
  const mid = (band[0] + band[1]) / 2;
  const fit = userSat >= band[1] ? 2 : userSat >= mid ? 1 : userSat >= band[0] ? 0 : -1;
  if (isNaN(acc)) return fit >= 1 ? 'm' : 'r';
  if (acc < 10)  return 'r';
  if (acc < 22)  return fit >= 2 ? 'rm' : 'r';
  if (acc < 40)  return fit >= 2 ? 'm' : fit >= 1 ? 'rm' : 'r';
  if (acc < 60)  return fit >= 1 ? 's' : fit >= 0 ? 'm' : 'rm';
  return               fit >= 1 ? 's' : fit >= 0 ? 's' : 'm';
}
```

五档文案：`r` 偏冲 / `rm` 冲·适中 / `m` 适中 / `s` 较稳 / `h` 看综合。

**判断依据**（H4，悬停徽标可见）——四段拼起来：

```
SAT {分数} {高于上沿 / 区间上半段 / 区间下半段 / 低于下沿}({该校区间})
整体录取率 {acc}{录取率<10% 时补一句}
未纳入：GPA与课程体系 / 专业与学院 / 国际生身份 / 资助需求 / 申请批次
```

**A4 · 缩放控件（左上角 ＋ / － / 复位）**

| 按钮 | 行为 |
| --- | --- |
| ＋ | 以**视口中心**为锚点 `zoomAt(cx, cy, 1.35)` |

**A7 · 悬停提示（鼠标）与点按（触屏）**

| 项 | 规则 |
| --- | --- |
| 触发 | `pointermove` 命中点后延迟 120ms 显示，避免快速划过时闪 |

| 触屏 | 不做悬停，点按直接走 A8 的 `BROWSE` |
| 隐藏 | 光标移出点，或本次指针序列发生过平移（`moved === true`）时立即隐藏 |

> `hovered` 只存 `en` 字符串，**不存坐标**。坐标留在事件里用完即弃——
> 否则每次 `pointermove` 都会进一次 reducer，113 个点的场景下会拖慢主线程。

### 7.1 测试框架

项目**目前没有任何测试框架**（`package.json` 里没有 test 脚本）。本方案引入：

| 依赖 | 用途 | 理由 |
| --- | --- | --- |
| `vitest` | 单元测试与组件测试 | 项目是 ESM + TypeScript + Next 16，Vitest 零配置即可跑 TS，不需要额外 babel |
| `@testing-library/react` | 组件测试 | 按「用户看到什么」断言，不依赖内部实现 |
| `jsdom` | 浏览器环境 | 组件测试需要 DOM 与 `localStorage` |
| `tsx` | 跑 TS 构建脚本 | Docker 基础镜像 `node:20-alpine` 不支持原生执行 `.ts` |

**不用 `vitest/globals`**——测试文件显式 `import { describe, it, expect } from 'vitest'`，
这样 `next build` 的 TypeScript 检查不需要额外配置就能通过。

**三层分工**：

```
单元测试   lib/ 下的纯函数              —— 覆盖重点，行覆盖率 >= 80%
组件测试   关键交互（对比位、档案、工具栏）—— 只测行为，不测样式
联调       跨模块 / 跨页面 / 构建产物      —— 见 7.4，必须手工执行并留记录
```

### 验收点里两处**实现方式**的说明

- **语境条不在服务端渲染**：URL 查询串走 `useSyncExternalStore`，服务端快照返回空串，
  客户端 hydration 后补上。换来的是 `/colleges` 保持**静态预渲染**（构建产物为 `○`）。
- **`html[data-font]` 是全局的**：字号三档写在根元素上，离开 `/colleges` 时移除，
  不影响其他页面。地图标注用 SVG `viewBox` 下的绝对字号，**不随字号变**（§6.14 的预期）。
