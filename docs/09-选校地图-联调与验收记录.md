### 第 3 / 5 条为什么是黄灯

语境条（"来自现场全景 · 清除"）**故意不在服务端渲染**：URL 查询串走
`useSyncExternalStore`，服务端快照返回空串，客户端 hydration 后立刻补上。
这样 `/colleges` 才能保持静态预渲染（`○`），代价是语境条会晚一帧出现。

所以：

- **能自动验的部分**（参数解析、文案、无参数时不渲染）已经验了；
- **需要通过浏览器点的部分**（点入口 → URL 带参数 → 点清除 → 后退一次回到来源页）
  留给现场走查。

## 五、实施过程中发现并处理的方案问题

以下五处是**方案与实现之间必须做的判断**，都记在这里，避免下次重新讨论。

### 5.1 §6.15 说"单语字段的说明写进第 2 / 13 / 14 节"——位置写错了

第 2 节是区位、第 13 节是气质、第 14 节是点评，这三处**源数据是中英双份**
（`cz`/`ce`、`tz`/`te`、`nz`/`ne`），英文模式下本来就切得干净，不需要说明。

真正的单语字段在这三节：

| 单语字段 | 渲染位置 |
| --- | --- |
| `idef_t`（国际生认定原文） | 第 9 节「本科国际生比例」内 |
| `ivw_t`（面试政策概括） | 第 11 节「面试政策」内 |
| `essays`（文书提炼） | 第 12 节「小文书」内 |

**实现按实际位置加说明行**（英文模式下显示中文原文 + 一行
"This section comes from Chinese-only source data and is shown in Chinese."）。
`docs/08` §6.15 那句"第 2 / 13 / 14 节"应作废。

### 5.2 `alert`（政策提醒）在 15 节里没有归处

`alert` 是字段契约里的一列（全库仅 4 所有，例如"2027-28 申请季起恢复要求提交标化"），
但 `docs/06` 的 15 节里没有它该待的地方。

**实现**：放在档案头部校名下方，作为一行提示，只有有值时才出现。
这样既不插进 15 节的顺序里，也不会让这条信息消失。

### 5.3 点位散开的算法与方案描述不同

§6.5 写的是"以簇质心为中心，按距离从小到大依次外推"。实现改成**成对松弛**：
对屏幕距离小于 12px 的点对各退一半，迭代到没有冲突或位移触到 24px 上限。

**理由**：质心外推会整体搬动整簇，让整片密集区偏离真实地理位置；成对松弛只动冲突的两个点，
且同样满足"间距不小于 12px，或外推不超过 24px"这条验收标准。

**没有变的**：散开只改渲染坐标，拾取一律用原始 `x`/`y`（§6.5 的关键坑），有专门单测。

### 5.4 目录清单与实现的两处出入

| 方案 §5.1 写的 | 实际 |
| --- | --- |
| `export-shortlist.ts` | `export-shortlist.tsx` —— 它是个 React 组件，不是纯函数 |
| `colleges-detail.tsx` | **未单独建文件**。侧栏三段布局只有 20 行 JSX，直接写在 `app/colleges/page.tsx` 里，单独开文件反而多一层跳转 |

### 5.5 州名标注缺 DE / RI / DC 是沿用，不是漏做

底图 48 条州名标注里没有 DE、RI、DC —— 因为这三个州太小，放不下标签。
这是参考实现的取舍，`docs/08` §6.4 已登记。**这三个州里的院校点照常渲染**，
底图也照常画，只是没有州名文字。

### 关键取舍

- **为什么从参考实现取那 6 块陆地**：加拿大 / 墨西哥 / 巴哈马 / 古巴 / AK / HI 在公开的
  美国州界数据里没有；要么再引一份世界地图数据（新依赖 + 新投影），要么自己给 AK / HI
  定插图投影手调参数。而参考实现里这 6 块**已经是同一套投影下的 viewBox 坐标**，
  取用最省事也最忠实。取法是按**包围盒**识别（那 57 条 path 没有 id / class / data-*），
  规则和结果都写进 `data/us-land.json`，另有一次性脚本 `scripts/extract-us-land.ts` 留档。
- **为什么用 CSS `drop-shadow` 而不是 SVG `<filter>`**：色值可以留在 `globals.css`，
  组件里不出现字面量色值（配色守卫测试会拦）。
- **没有画波多黎各等属地**：一期没有院校在那里，也不在地图叙事范围内。

### 第四轮反馈：海洋渐变露接缝 + 靠边的学校点不中

这两条**是同一个根因**：SVG 元素盒子与 viewBox(975:610) 的宽高比不一致时，
`preserveAspectRatio="xMidYMid meet"` 会等比缩放后居中，左右留白。留白区不属于 viewBox：

- 留白区显示的是容器底色，而内容区是渐变 → 左右两条竖直接缝（用户红框的位置）；
- 坐标换算没扣掉留白 → 换算偏移 `|54.9 − 0.1125x|`，超出拾取阈值 15.6 后点不中，
  反推 **x < 349 与 x > 626 的院校全部点不中**（西海岸 + 东海岸），
  只有中间大平原那一条能点 —— 正好对应用户截图里左右两端的红框。

修法：

1. **海洋改成单一颜色**，且与容器底色取同一个值 → 接缝在物理上不存在；
2. 地图里所有「屏幕坐标 ↔ viewBox 坐标」的换算改走 `mapRect()`（扣掉留白的**内容区**），
   涉及拾取、悬停、滚轮缩放锚点、拖拽增量、点位散开的像素阈值。

守护：`colleges-map.test.tsx` 把元素盒子的宽高比刻意设成 **1200:500**（左右各留白 200px），
断言最靠左的院校（x < 60）也点得中。**这条能证伪**：把 `mapRect()` 换回
`svg.getBoundingClientRect()`，测试立刻挂掉 2 条（已实测）。

### 第五轮反馈：详情栏不再常驻

原来的版面是「左地图 62% + 右详情栏 38%」**常驻**，两个视图都是。问题是：

- 地图视图一进来就被挤掉 38% 宽，可这时候还没选任何学校，右边是空的；
- 表格视图右边也杵着一个空栏，把 23 列的表格挤得更窄。

改成按状态决定：

| 视图 | 选中了院校 | 版面 |
| --- | --- | --- |
| 地图 | 否 | 地图铺满整行（`h-[70vh]`） |
| 地图 | 是 | 左地图 62% + 右详情 38%，两栏同高同底（`h-[58vh]`） |
| 表格 | — | 表格铺满整行，**不出详情栏**（点行仍切回地图并打开详情） |

**连带问题与解法**：对比位托盘原来长在详情栏顶部，详情栏一收，已收集的学校就没地方显示了。
规则改成 —— 详情栏收起时（含表格视图），只要对比位里有学校，就把托盘渲染到内容区上方。
收集到的东西任何时候都不会消失。点托盘里的槽仍会把那一所切回浏览位（在地图视图里即打开详情栏）。

顺带一处：工具栏的**搜索联想**在表格视图里点了原本没有任何可见反应（详情栏不出现），
现在点联想会先切回地图视图再打开详情栏 —— 语义就是"我要去看这所学校"。

**守护**：新增 `src/app/colleges/__tests__/page.test.tsx`（4 条，第一次给页面级行为上锁），
断言的就是上面这张表的每一行：

3. 切表格视图后 `.colleges-split` 消失、详情栏消失、表格还在；

### 11.2 关键边界（这条决定功能对不对）

**日界按北京时间（+08:00）手算，不用数据库的 `current_date`。** 托管库跑 UTC，
中国早上 8 点的活动在库里还是前一天 24 点——用数据库的"今天"会把整场算到昨天，
大屏开场就是空的。单测把这条钉死了：

```
北京时间 2026-09-18 07:00 === UTC 2026-09-17 23:00  →  beijingDate() = "2026-09-18"（不是 17）
某一天的范围 = [当日 00:00+08:00, 次日 00:00+08:00)  →  左闭右开，跨度正好 24 小时
边界那一刻（end）算下一天
```

## 十四、Excel 批量导入修好了（2026-09-18，现场反馈）

### 14.1 事故

工作人员上传自己做的 Excel（`孩子信息案例.xlsx`，12 个孩子），**12 行全部报"缺少全部字段"**，
报错刷了一屏。

**根因**：`/api/children/bulk` 只认**英文键名**（`englishName` / `dreamSchool`…），
而任何自己做的表都用**中文列名**。实测那张表的表头是：

```
孩子的英文名 | 年龄 | 梦想学校 | 兴趣 | 喜欢的活动 | 孩子自我描述 | 家长观察 | 梦想职业（选填）
```

→ 一列都对不上 → 每行都判"7 项全缺"。**这个通道对它的目标用户（工作人员）实际是坏的**，
而且报错方式（逐行列一遍）把真正的原因埋在了一屏文字里。

### 14.2 修法

新增 `lib/bulk-import.ts`（纯函数，12 条单测）：

| 项 | 做法 |
| --- | --- |
| 列名归位 | 中文表头、带括号的表头（`梦想职业（选填）`）、原英文键**都认**；比较时去掉括号内容/空格/下划线/大小写 |
| 不做模糊匹配 | 认不出的列**直接忽略**，不猜——宁可报"这个列名不认识"，也不要把数据写进错的字段 |
| 别名撞车当场报 | 同一个归一列名指向两个字段时**直接抛错**（那是会把数据写错列的配置事故） |
| **报错改成人话** | 每行都缺同样的项 → 判定为**表头问题**，给一句"这些列没读到，第一行请这样写：…"，**不再逐行刷屏**；只有个别行缺 → 才逐条点名（这时逐条报才有用） |

## 十五、批量生成画像"要跑三次"（2026-09-18，现场反馈）

### 15.1 现象

现场反馈：**Excel 导入 12 个孩子，点一次「生成画像」跑不完，要重试两次才全生成。**

### 15.2 复现（用真接口，不打桩）

`src/tmp/repro-analyze.ts`（临时脚本，gitignore）造 12 条"刚导入、没画像"的记录，
逐条打真实 `/api/children/analyze`，记录每条的 HTTP 状态、耗时与错误原文：

```
❌ id=118 HTTP 500 8522ms  模型返回格式异常，请重试
结果：成功 8/12，失败 4
```

**稳定复现，且失败不可预测**——同一批输入、同一个模型，失败的是哪几条每次都不一样。

### 15.3 根因（抓原始返回才看清，**第一版判断是错的**）

第一版推断是"没传 `max_tokens` → 输出被截断 → JSON 不完整"，并据此加了 `max_tokens`。
**复跑仍然失败**，于是绕过应用直接打 AI98 端点、把原始响应打出来
（`src/tmp/diag2.ts`，同一批 12 条，`max_tokens` 传与不传各跑一轮）：

```
########## max_tokens = 2048 ##########      ########## max_tokens = (不传) ##########
❌ #5  HTTP 200 finish=stop  …  JSON.parse failed   ❌ #2  HTTP 200 finish=stop  …  JSON.parse failed
--> 成功 10/12                                  --> 成功 8/12
```

**所有失败样本的 `finish_reason` 都是 `stop`——根本没有截断。** 打开失败样本的 content：

```json
"reason": "参与机器人社团，自述"喜欢把一个东西拆开看清楚它怎么运转"体现出对机械结构的兴趣"
```

模型引用孩子原话时用的是**英文直角双引号**，且没有转义 → `JSON.parse` 直接失败。
这是**模型的正常行为**（它觉得在复述原话），不是偶发故障，所以"再点一次"只能靠运气。

> `max_tokens` 保留了（不显式给就由中转站决定默认值，长输出有被截断的风险），
> 但它**不是**这次的原因——`lib/ai98.ts` 的注释已按事实改正。

### 15.4 修法

| 层 | 改动 |
| --- | --- |
| **容错解析**（主要修法） | 新增 `lib/model-json.ts`：`parseModelJson()` 先剥围栏/前后废话取最外层 JSON，直接 `JSON.parse`；失败才把**字符串值内部没转义的双引号**补反斜杠（判定方式：引号后第一个非空白字符是 `:` `,` `}` `]` 或结尾 = 正常收尾，否则是内容里的引号）再解析一次。字符串里的真实换行同样一并转义 |
| **提示词收紧**（降低发生率） | 两处 analyze prompt 追加：`reason` 里引用原话一律用中文引号「」，禁止在 JSON 字符串里出现英文双引号 |

## 十六、必填项从 7 项收到 3 项（2026-09-18，现场反馈）

### 16.1 改了什么

**只有三项必填：孩子的英文名、梦想学校、喜欢的活动。** 年龄、兴趣、孩子自我描述、家长观察、
梦想职业全部改成选填，**表单上不再打星号**。

理由：现场家长常常只想填这两三样，卡在"年龄 / 自述 / 家长观察"上反而录不进来；而这些字段
空着完全不影响画像——AI 只根据写了的内容给方向，prompt 里本来就写着"不得编造孩子经历"。

### 16.2 动了哪几处（关键是**只有一份定义**）

`lib/bulk-import.ts` 的 `REQUIRED_FIELDS` 是唯一来源，三个地方从它派生，不再各写一份：

| 位置 | 改动 |
| --- | --- |
| `/api/children`（家长提交） | 必填只校验那三项；报错的字段名用 `FIELD_LABEL` |
| `lib/bulk-import.ts` 的 `checkBulkRows`（Excel / 文本导入） | 必填只校验那三项；年龄改成"填了才校验" |
| `/register` 页面 | 星号去掉，`required` 只给那三项，表单上方加一句"必填只有三项…" |

### 16.3 年龄选填 → `age` 列改成可空（有迁移）

年龄选填后不能再用 `0` 占位——0 会被下游当成"0 岁"读出去（`/api/children/summary` 是公开大屏
接口）。所以**真的把列改成可空**：`drizzle/0004_parched_human_robot.sql`
（`ALTER TABLE "children" ALTER COLUMN "age" DROP NOT NULL`，非破坏性）。
**这是本项目的第 5 个迁移**，发布时平台照 `luffy.migrate` 自动 apply。

> 本地也 `drizzle-kit migrate` 过了，实测只填三项提交后 `age` 存的是 NULL（不是 0）。

### 16.4 顺带修的：文本批量录入多了一种写法

必填收到 3 项后，原来"一行一个字段、按固定顺序"的写法要求**空字段也得占一行**，
对着一堆空行数位置太容易错。所以 `parseTextBlock()` 增加了**带字段名**的写法（两种都认）：

```
孩子的英文名: Emma
梦想学校: RISD
喜欢的活动: 绘画、做手账
```

一行一个「字段名: 内容」，顺序随便、没写的字段整行不写。字段名复用 Excel 那张列名别名表
（`HEADER_MAP`），所以中文名、英文键名、全角冒号都认；一行字段名都没认出来时，退回原来的
按顺序读法。
