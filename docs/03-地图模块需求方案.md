## 一、地图在四个地方出现

同一个地图组件，四种用法。数据和交互共用一套，只是尺寸和可操作性不同。

| # | 位置 | 回答什么问题 | 数据源 | 尺寸基准 | 能操作吗 | 优先级 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `/explore` · 现场大屏 · **方向图层（主）** | 这些方向通向美国的哪些地方 | `school_recommendations` | 1920×1080 全屏 | 点击看详情 | P1 必做 |
| 2 | `/explore` · 现场大屏 · **梦想院校图层（辅）** | 孩子心里想着哪里 | `children_universities` | 同上 | 图层切换 | P1 可延后 |
| 3 | `/child/[token]` · 单孩子画像 | 这个孩子的方向通向哪里 | `school_recommendations`（单条） | 手机 375px 宽 | 点击看详情 | P0 |
| 4 | `/` · 首页预览 | 活动的实时概览 | 同上（聚合） | 响应式 | 只读小图 | P1 |

**四个地方共用同一个渲染组件**，不做四套实现。差异只在参数：数据、尺寸、是否可交互、是否显示图例。

## 二、先把词定义清楚

| 词 | 定义 |
| --- | --- |
| **方向落点** | AI 根据孩子的兴趣特质推荐出来的"这个方向通向的院校"。一个孩子最多 3 个方向 × 每个方向 3–5 所院校 |
| **梦想院校** | 家长在报名表里**自己填**的院校原文（最多 3 个）。可能写简称、中文名、错别字 |
| **归一化** | 把家长填的原文或 AI 输出的校名，转成坐标表里的标准写法。命中才能上图 |
| **坐标表** | `data/university_coords.csv`，150–200 所美国院校的 `name / aliases / state / lat / lng`。**不是院校-专业库**，不含专业信息 |
| **光点** | 地图上的一个圆点，代表一所院校。圆的大小 = 有多少个孩子的方向通向这里 |
| **聚合** | 屏幕上挨得太近的几个光点，合并成一个显示 |
| **契合层级** | 单孩子画像里每条推荐的匹配程度，三档：**高度契合 / 值得了解 / 可以看看**（定义见 PRD 3.4.2）。大屏的聚合光点不带层级——那是很多孩子的共同结果，标一个人均层级会误导 |

## 三、两张图层的完整定义

### 3.1 主图层：方向地图

| 项 | 定义 |
| --- | --- |
| 英文标题 | `Where do these paths lead?` |
| 数据源 | `school_recommendations` 表 |
| 一句话 | 有 N 个孩子的**方向**通向这里 |
| 统计口径 | 同一个 `university_name` 被多少个**不同孩子**推荐过（一个孩子在同一所学校出现多次只算 1 次） |
| 默认状态 | **默认展示这一层** |
| 为什么是主图层 | 它回答的是产品核心问题；而且它不受家长填写准确度影响 |

### 3.2 辅图层：梦想院校地图

| 项 | 定义 |
| --- | --- |
| 英文标题 | `Where are they dreaming of?` |
| 数据源 | `children_universities` 表（归一化后命中坐标表的记录） |
| 一句话 | 有 N 个孩子把这里**填成了志愿** |
| 统计口径 | 同一个 `canonical_name` 被多少个不同孩子填过 |
| 默认状态 | 关闭，手动切换 |

### 3.3 叠加模式

两个图层同时显示时，用**形状**区分，而不是只用颜色——大屏是远距离观看，形状比颜色更容易分辨。

| 图层 | 形状 | 说明 |
| --- | --- | --- |
| 方向落点 | **实心圆**，深绿色系 | 填充色随人数深浅变化 |
| 梦想院校 | **空心圆环**，琥珀色 | 只有描边，内部透明 |
| 两者重合 | 实心圆 + 外圈圆环（同心双环） | 一眼看出"想去的地方，方向也确实通向这里" |

**叠加模式的价值**：现场能讲出有洞察力的故事——

| 现象 | 说明什么 |
| --- | --- |
| 圆环大、实心小 | 很多孩子心里想着这里，但他们的方向还没走到这里 |
| 实心大、没有圆环 | 孩子们还没听说过，这个方向其实可以通向这里 |
| 双环重合 | 有一批孩子的目标和方向已经对上了 |

## 四、数据怎么变成地图上的点

### 4.1 数据流

```
 school_recommendations          children_universities
   (AI 推荐，含校名)                (家长原文，含校名)
          │                                  │
          └──────────────┬───────────────────┘
                         ▼
                  归一化 (normalize)
          查 university_coords.csv 的 name / aliases
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
          命中坐标                未命中
              │                     │
      取 lat / lng / state      不进地图，
              │                  原文保留、列表里仍显示
              ▼
      按标准校名聚合，算人数
              │
              ▼
      算半径 + 分色 → 渲染光点
```

### 4.2 归一化规则

命中判定按顺序尝试，命中即停：

| 顺序 | 规则 | 例子 |
| --- | --- | --- |
| 1 | 精确匹配 `name` | `Stanford University` → 命中 |
| 2 | 精确匹配 `aliases` 任一项 | `USC` → `University of Southern California` |
| 3 | 去空格、去标点、转小写后再匹配 | `university of southern california` → 命中 |
| 4 | 去掉 `University of` / `The` 等前缀后匹配 | `Southern California` → 命中 |
| 5 | 全部失败 | 记为未命中，不上图 |

**必须统一写法的原因**：如果不归一化，`USC` 和 `University of Southern California` 会被当成两所学校，地图上散成两个点，人数也被拆开。

常见别名示例（完整清单在坐标表的 `aliases` 列）：

| 原始输入 | 归一化结果 |
| --- | --- |
| USC / 南加州大学 | University of Southern California |
| NYU / 纽约大学 | New York University |
| MIT / 麻省理工 / 麻省理工学院 | Massachusetts Institute of Technology |
| Stanford / 斯坦福大学 | Stanford University |
| UCLA / 加州大学洛杉矶分校 | University of California, Los Angeles |
| UC Berkeley / 伯克利 | University of California, Berkeley |
| RISD / 罗德岛设计学院 | Rhode Island School of Design |
| CMU / 卡内基梅隆 | Carnegie Mellon University |

### 4.3 未命中坐标表怎么办

分三个阶段处理，原则是**宁可少一个点，也不要在一个错误的位置上放一个点**。

| 阶段 | 处理方式 |
| --- | --- |
| 活动前彩排 | 把 AI 实际推荐出来的院校跑一遍，凡是不在坐标表里的，补进坐标表。**目标是把缺口清零** |
| 活动当天（大屏） | 未命中的不画点。地图右下角显示一行小字：`另有 3 所院校未在地图上标注` |
| 家长端（画像） | 未命中的院校**仍然出现在推荐列表里**，旁边标注"暂未在地图标注"，不影响家长看到内容 |

## 五、坐标系与底图

### 5.1 投影

- 使用 **Albers USA** 投影（美国地图的标准画法）；
- 阿拉斯加与夏威夷自动缩放到左下角的小图区，不占主图空间；
- 底图数据：`us-atlas` 的 `states-albers-10m.json`，约 100KB，随代码打包；
- 院校坐标：**WGS84 经纬度**，直接投到 Albers 投影上，不需要任何坐标转换（GCJ-02 偏移只影响中国境内数据）。

### 5.2 底图两套，可切换

| 代号 | 底图 | 打开方式 | 用途 |
| --- | --- | --- | --- |
| **A**（默认） | 州界简图，米白底 + 浅灰州界线 | 网址不带参数 | 大屏主力，干净、克制 |
| **B** | 真实地图质感（自托管矢量瓦片） | 网址带 `?basemap=street` | 想要真实地理感时切换 |

**切换实现**：读网址参数即可，不做后台开关，不改代码。活动前用现场那块屏幕打开两个版本比一次，选一个留下。

**无论用哪套，都不依赖在线地图服务**——底图文件全部本地打包。

### 5.3 底图的视觉要求（方案 A）

| 元素 | 规范 |
| --- | --- |
| 陆地填充 | `#F4F7F5`（极浅米绿） |
| 州界线 | `#D8E3DE`，0.75px |
| 海岸线 | `#C6D8D0`，1px |
| 背景 | 透明（跟随所在区块底色） |
| 阿拉斯加 / 夏威夷小图 | 同样式，不加额外装饰 |

**不要**给州填不同颜色——颜色要留给光点，底图抢色会让人看不懂哪个信息重要。

## 六、视觉规范

### 6.1 光点大小

按人数缩放，用**平方根**而不是线性——否则 1 人和 20 人的差距会大到看不见小点。

```
r = R_MIN + (R_MAX - R_MIN) * sqrt(n / N_max)

R_MIN = 7px     最小半径（1080p 基准）
R_MAX = 22px    最大半径（对应人数最多的那所学校）
n      = 这所学校被多少个孩子的方向通向
N_max  = 当前屏幕上最多的一所学校的人数
```

实际数值（假设 N_max = 20）：

| 人数 | 半径 | 直径 | 观感 |
| --- | --- | --- | --- |
| 1 | 10.4 px | 21 px | 小点 |
| 2 | 11.7 px | 23 px | 小点 |
| 3 | 12.8 px | 26 px | |
| 5 | 14.5 px | 29 px | 中等 |
| 8 | 16.5 px | 33 px | |
| 12 | 18.6 px | 37 px | 明显 |
| 20 | 22.0 px | 44 px | 最大 |

4K 屏按 1920 基准等比放大 2 倍。

### 6.2 光点颜色

按人数占最大值的比例分三档。**颜色和大小是冗余编码**（同时表达同一个信息），这样远距离靠颜色、近距离靠大小都能读出来。

| 档位 | 条件 | 填充色 | 含义 |
| --- | --- | --- | --- |
| 高 | n ≥ 0.6 × N_max | `#1F4D3A` 深绿 | 热门方向落点 |
| 中 | 0.25 × N_max ≤ n < 0.6 × N_max | `#3E7A5E` 中绿 | |
| 低 | n < 0.25 × N_max | `#7FA893` 浅绿 | |
| 选中 / hover | 任意 | 原色 + `#C9A227` 琥珀色描边 2px | 与梦想图层的琥珀色呼应 |

梦想院校图层统一用琥珀色 `#C9A227` 描边、内部透明，**不按人数分档**——辅图层不需要那么强的表达。

### 6.3 标签（院校名）

| 场景 | 显示规则 |
| --- | --- |
| 默认（大屏） | 只显示人数 **Top 5** 的院校名 |
| hover / 点击 | 该院校名立刻显示 |
| 自动轮播 | 轮播到的那所显示 |
| 单孩子画像（手机） | 全部显示（最多 15 所，不会挤） |
| 字号 | 大屏 16px（1080p 基准），画像页 12px |
| 位置 | 光点右下偏移 6px，带 1px 白色描边防压线 |
| 重叠处理 | 两个标签碰撞时，低优先级的那个隐藏（不挪位置，避免误读） |

### 6.4 图例

放在地图**左下角**，半透明卡片：

```
   ⬤  方向通向这里的孩子数
   1  ⬤      5  ⬤      20  ⬤
   ─────────────────────────
   ◯  梦想院校（孩子自己填的）
```

单孩子画像页**不显示图例**——只有一个孩子，没有"人数对比"这回事，光点大小保持最小值恒定。

### 6.5 动效

| 动作 | 效果 | 时长 |
| --- | --- | --- |
| 首次入场 | 光点按人数从大到小依次淡入 + 从 0 放大到目标半径 | 每个间隔 60ms，总时长 ≤ 1.2s |
| 数据刷新 | 已有光点半径平滑过渡；新光点淡入 | 400ms |
| 图层切换 | 交叉淡入淡出，不重建 DOM | 500ms |
| 选中 | 放大到 1.15 倍 + 琥珀描边 | 200ms |
| 聚合展开 | 聚合点炸开成环形排列 | 350ms |

**刷新不能闪屏**——已存在的光点不能先消失再出现，否则大屏看起来像在抽风。

## 七、交互设计

### 7.1 现场大屏 `/explore`

| 交互 | 行为 |
| --- | --- |
| 点击光点 | 右侧滑出详情面板（见 7.4），地图其余部分轻微变暗 |
| 点击空白处 | 关闭详情面板 |
| 鼠标悬停 | 光点放大到 1.15 倍 + 显示院校名 |
| 无人操作 20 秒 | 开始自动轮播 |
| 自动轮播 | 按人数 Top 5 循环，每所停留 8 秒，自动展开详情面板 |
| 有人操作 | 立刻停止轮播；再空闲 30 秒后重新开始 |
| 滚轮 / 缩放 | **禁用**。地图固定视野，避免误操作把地图拖歪 |
| 触摸屏 | 支持点击；不支持双指缩放 |

**为什么禁用缩放**：大屏是给别人看的，不是给人操作的。一旦被人拖走或缩放，后面看到的观众看到的就只是一张奇怪的图。

### 7.2 单孩子画像 `/child/[token]`

| 交互 | 行为 |
| --- | --- |
| 页面加载 | 地图先渲染，光点依次亮起；下方同时给出院校列表 |
| 点击光点 | 展示该院校的推荐理由（direction 和 reason 两句话） |
| 点击列表里的院校 | 地图上对应光点高亮，并让地图滚动到可见区域 |
| 光点大小 | 统一大小（一个孩子，没有人数差异），选中项放大 |
| 未命中院校 | 列表里照样出现，标注"暂未在地图标注" |

**地图和列表必须双向联动**——这是手机上最容易做错的地方：只能点地图不能点列表，用户会很难受。

### 7.3 首页预览 `/`

- 只读小图，**不可点击光点**（点整块区域跳到 `/explore`）；
- 不显示图例、不显示标签；
- 光点统一大小，因为这块区域太小，大小差异看不出来只会显得脏。

### 7.4 详情面板内容

大屏和画像页共用一个组件，字段按场景裁剪。

| 字段 | 大屏 | 画像页 |
| --- | --- | --- |
| 院校全名（英文） | 有 | 有 |
| 所在州 | 有 | 有 |
| 有多少个孩子的方向通向这里 | 有 | 无（只有一个孩子） |
| 对应的专业分布（Top 3，带横条） | 有 | 有 |
| 年龄分布 | 有 | 无 |
| 为什么推荐给你（AI 的 reason） | **无** | 有 |
| 官网搜索链接 | 无 | 有 |

**大屏不显示推荐理由**，因为那句话是基于某个具体孩子的表达写的，虽然不提名，但容易对上号。这是隐私边界。

## 九、技术要求

### 9.1 性能

| 项 | 要求 |
| --- | --- |
| 光点数量上限 | 去重后通常 60–120 所，按 200 所设计 |
| 首次渲染 | ≤ 800ms（含 100KB TopoJSON 解析） |
| 刷新 | 每 30 秒拉一次聚合数据，只更新变化的属性，不重建 DOM |
| 内存 | 连开 8 小时不增长（不累积定时器、不泄漏事件监听） |
| 断网恢复 | 拔网 10 分钟插回，30 秒内自动回到最新状态，不白屏 |

### 9.2 数据接口

地图只需要一个聚合接口，**不要让前端拿全量明细再自己算**：

```
GET /api/map/aggregate?layer=paths|dreams|both

{
  "layer": "paths",
  "total_children": 86,
  "unmapped_count": 3,
  "schools": [
    {
      "name": "University of Southern California",
      "state": "California",
      "lat": 34.0224, "lng": -118.2851,
      "count": 12,
      "programs": [
        {"name": "Game Design", "count": 6},
        {"name": "Interactive Media", "count": 4},
        {"name": "Film & Media", "count": 2}
      ],
      "ages": {"12-14": 5, "15-17": 7}
    }
  ]
}
```

`unmapped_count` 就是"另有 N 所院校未在地图上标注"的那个 N。

单孩子画像用另一个接口，只返回这一个孩子的推荐：

```
GET /api/child/{token}/map
```

### 9.3 隐私

- 聚合接口**只返回人数，不返回任何孩子标识**——连匿名 ID 都不给；
- 大屏详情面板不显示 AI 的推荐理由（可能对应到具体孩子的表达）；
- 单孩子接口必须校验 token，前端不直连数据表。

## 十、验收标准

### 10.1 数据正确性

- [ ] 抽 20 所院校，地图上的光点人数与数据库聚合结果一致；
- [ ] `USC`、`南加州大学`、`University of Southern California` 三种写法在地图上只出现一个点；
- [ ] 一个孩子在同一所学校出现多次时，只计 1 人；
- [ ] 未命中坐标表的院校，在地图上不出现，但在画像列表里能看到。

### 10.2 大屏

- [ ] 打开网址即用，无登录、无前置操作；
- [ ] 1920×1080 / 2560×1440 / 3840×2160 下都铺满不变形；
- [ ] 光点按人数分三档颜色，远处能分辨深浅；
- [ ] 点击光点滑出详情面板，点击空白关闭；
- [ ] 空闲 20 秒开始自动轮播 Top 5，有人操作立刻停止；
- [ ] 滚轮和双指缩放被禁用，地图不会被拖歪；
- [ ] 30 秒刷新时光点不闪烁、不整体重绘；
- [ ] 连开 8 小时无内存增长；
- [ ] 拔网 10 分钟插回自动恢复。

### 10.3 单孩子画像

- [ ] 地图与下方列表双向联动（点地图高亮列表，点列表高亮地图）；
- [ ] 375px 宽手机上无横向滚动、地图不超出容器；
- [ ] 未命中的院校在列表里标注"暂未在地图标注"；
- [ ] 院校名只显示大学名，不含学院名。

### 10.4 底线检查

- [ ] 地图上**不出现任何孩子的姓名**；
- [ ] 详情面板**不出现**"冲刺 / 匹配 / 保底"、"录取概率"、"适合"等字样；
- [ ] 底图资源全部本地加载，断网后地图仍能显示（数据除外）。
