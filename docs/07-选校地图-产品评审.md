## 一、总体判断

**方案把一个「申请作战台」的功能壳，套在了「成长方向探索」的产品上——页面的主轴（排名、录取率、早申杠杆、冲稳保分档）与产品的主轴（兴趣 → 方向 → 通向哪里）指向相反，而核心链条在 `/colleges` 上是断的。**

一句话：按现在这个方案做完，家长在这一页得到的是「我够不够得着」，不是「我的方向通向哪里」。

这不是价值判断，有可核对的结构性证据：

**证据 1 · 详情卡 15 节的成分**

| 节 | 内容 | 性质 |
| --- | --- | --- |
| 1 | 排名（US News + QS） | 申请 |
| 2 | 所在城市与州 | **方向** |
| 3 | 学费 | 申请 |
| 4 | 申请批次（ED/EA/RD） | 申请 |
| 5 | 最近申请季截止日期 | 申请 |
| 6 | 录取率（早申/RD/整体/转学） | 申请 |
| 7 | 申请人数 | 申请 |
| 8 | 在读本科男女比例 | 申请 |
| 9 | 本科国际生比例 | 申请 |
| 10 | 语言要求与标化 | 申请 |
| 11 | 面试政策 | 申请 |
| 12 | 小文书 | 申请 |
| 13 | 院校气质 | **方向** |
| 14 | 一句话点评 | **方向** |
| 15 | 数据信号（条件渲染） | 申请 |

15 节里 **12 节是申请数据，3 节与「这所学校是什么样」有关**。

**证据 2 · 洞察榜 5 个标签全是申请策略维度**：早申倍数高 / 国际生占比高 / 转学率较高 / 申请池较小 / 不看标化。没有一个是「方向」维度。

**证据 3 · 黑马匹配**：输入 SAT 分数，把院校分成「偏冲 / 冲·适中 / 适中 / 较稳」四档，是拿孩子去对院校，不是看方向。

**证据 4 · 与产品的其他页面零连接**：`docs/05` 与 `docs/06` 全文没有一处定义 `/colleges` 与 `/explore`、`/child/[token]` 之间的入口。

## 二、必须改

### M1 · 页面与核心链条断开，没有任何入口互通

**问题**：`/colleges` 与 `/explore`、`/child/[token]` 之间没有任何链接。家长在画像页看完三个方向，没有路径走到地图；在地图上逛完，也回不到自己孩子的方向。

**证据**：`docs/05` 第一节只定义了「入口＝顶部导航第 3 项」；`docs/06` 第二节只画了导航。全文无互通设计。

**为什么**：产品的核心链条是「兴趣特质 → 成长方向 → 方向通向哪里 → 地图」。地图是链条的**终点**，终点必须有入口。

**对用户的影响**：家长在画像页看到「艺术方向」时，正处在「这条路通向哪」的情绪高点上，页面没有任何下一步——这个情绪点被浪费。反过来，地图页变成孤岛，家长不知道「我为什么要看这些学校」。

**怎么改**：

- `/child/[token]` 的每个方向卡下方加入口：`看看这个方向通向哪些学校 →`，跳 `/colleges`
- `/explore` 底部加同样的入口
- `/colleges` 顶部加语境条：`来自成长画像 · 艺术方向 · 清除`（URL 参数携带，**不筛选数据**）
- **不做方向筛选**——113 所数据里没有「院校 ↔ 方向」的映射，做不了。硬做等于编数据

### M2 · 复刻范围里混入了 CMC 的营销转化件

**问题**：`docs/05` 第六节写了「CMC 的商业转化组件不复刻」，但实际列入 1:1 范围的功能里，有一部分**本身就是转化漏斗**。

**证据**（CMC 源码，逐条摘出）：

| 键 | 内容 | 出现位置 |
| --- | --- | --- |
| `hkTips` | 「…数据说不了的——这所学校对你孩子这类背景的真实偏好、文书怎么写才立得住——是顾问一对一的部分。会员可预约 15 分钟讲解（私信小助手）。」 | **每张详情卡底部，无条件渲染** |
| `hkFavCta` | 「→ 导出清单,发小助手领免费点评」 | 收藏区 |
| `hkMatch` | 「完整定位(纳入GPA/专业/身份)→ 黑马定位报告」 | 黑马匹配区 |
| `rptTitle` / `rptBody` / `rptCta` | 「🐎 黑马定位报告 · 把『初步区间』变成『完整定位』」…「私信 CMC 小助手，回复『定位』了解详情」 | 黑马匹配弹窗 |

**关键发现**：黑马匹配的**免责声明本身就是转化钩子**——`rptBody` 原文写的是「地图上的初步区间只用了『SAT×录取率』两个维度，置信度低」，紧接着卖「完整版」。所以「加免责说明」并不能中和它，那句免责说明在设计上就是漏斗的第一环。

**为什么**：这些话术的设计目的是把用户推向「私信小助手」。HFI 是家长成长营，接进来等于在自己的产品里替第三方导流。

**对用户的影响**：家长在 HFI 的页面上被推销第三方留学顾问，产品信任度直接受损。

**怎么改**：把上述四处 + 黑马匹配弹窗整块列入「明确不复刻」，验收时**逐字核对文案**，不留「顾问 / 小助手 / 私信 / 定位报告」字样。功能可以保留，话术必须清空。

### M3 · 第 15 节的名字和性质都记错了

**问题**：`docs/05` 与 `docs/06` 都写「第 15 节『冲刺策略提示』」，并花了一整节讨论要不要给它改名。**原文里没有这个节名。**

**证据**（CMC 源码）：

```js
${(tips=>tips.length
    ? sec(15, `${t.dTips} <span ...>${t.dTipsNote}</span>`, tips.map(x=>`<div class="dessay">🐎 ${esc(x)}</div>`).join(''))
    : '')(strategyTips(s))}
...
dTips:'CMC数据信号',
dTipsNote:'公开数据中的观察信号,自动生成 · 非录取预测,个案策略以顾问一对一为准'
```

三条更正：

1. 第 15 节的真实标题是 **「CMC 数据信号」**（源码键 `dTips`），不是「冲刺策略提示」
2. 它是**条件渲染**：只有 `strategyTips(s).length > 0` 才出现。触发条件是「早申录取率 ÷ RD 录取率 ≥ 2.5」。实际统计：**113 所中只有 14 所（12%）**会显示这一节
3. 每条信号前带 **🐎** 标记（黑马功能的品牌符号），这个标记不该复刻

**为什么**：把不存在的节名写进规格，会直接带进实现——开发会去造一个原版没有的区块。同时「是否保留」的讨论建立在错误前提上。

**对用户的影响**：不影响体验，但会让这一节的工作量评估和验收标准全错。

**怎么改**：`docs/05` 与 `docs/06` 统一改为「第 15 节 · 数据信号（Data Signals）」，写明条件渲染与 12% 触发率，去掉 🐎。

### M4 · 数据缺省率没进方案，界面会出现大量空白

**问题**：方案只写「113 所、42 个字段」，没写字段缺失情况。按 1:1 复刻、15 节固定渲染，缺失字段会显示成空白或 `null`。

**证据**（对 `tmp/cmc_data.json` 实际统计）：

| 字段 | 缺失数 | 占比 | 落在哪一节 |
| --- | --- | --- | --- |
| RD 录取率 `rr` | 65 | 58% | 6 录取率 |
| 早申录取率 `er` | 51 | 45% | 6 录取率 |
| 平均 GPA `gpa` | 48 | 42% | 对比表 |
| QS 排名 `qs` | 33 | 29% | 1 排名 |
| 国际生认定 `idef` | 33 | 29% | 9 国际生比例 |
| 小文书 `essays` | 19 | 17% | 12 小文书 |
| 学费 `tuition` | 17 | 15% | 3 学费 |
| 早申截止 `ea` | 17 | 15% | 5 截止日期 |
| 男女比 `mf` | 14 | 12% | 8 男女比例 |
| 转学率 `tr` | 12 | 11% | 6 录取率 |
| 申请人数 `apps` | 10 | 9% | 7 申请人数 |
| RD 截止 `rdd` | 7 | 6% | 5 截止日期 |
| 政策提醒 `alert_zh` | 109 | 96% | 仅 4 所有 |

**为什么**：超过一半的院校没有 RD 录取率，近一半没有早申录取率。第 6 节「录取率」在**一半以上的卡片上是残缺的**。

**对用户的影响**：卡片看起来「没做完」，家长以为数据丢了。对比表更严重——45%~58% 的格子是空的，横向比较失去意义。

**怎么改**：

- 每个字段定义**统一空值文案**（建议「未公布」），不留空白
- 第 15 节改为**条件渲染**（同 M3）
- 对比表增加数据完整度提示：缺项过多的院校在表头标注「数据不完整」，空格显示「未公布」而非留白

### M5 · 筛选器选项与数据不符

**问题**：`docs/05` B4 写「申请批次：有 EA / 有 ED1 / 有 ED2 / 限制性早申 REA」四项。

**证据**（实际统计）：113 所数据出现的批次类型共 **7 种**——`EA`、`ED0`、`ED1`、`ED2`、`REA`、`EAR`、`RD`。其中 **`ED0`（芝加哥大学）和 `EAR` 不在方案的四项里**，会被漏掉。

**为什么**：筛选器写死会漏数据，而漏掉的那所恰好是家长会主动搜索的学校。

**对用户的影响**：搜不到自己想要的批次，会认为筛选失灵。

**怎么改**：B4 改为**从数据动态生成选项**，并明确列出 7 种；顺序按 EA / ED0 / ED1 / ED2 / REA / EAR / RD。

### M6 · 数据来源合规没有写进方案

**问题**：`docs/05` 第 4.1 节只写「`data/colleges.csv`，113 所院校」，没有写这份数据从哪来、能不能用。

**事实**：数据来自 **CMC 会员版 HTML 解密**，是第三方整理成果。其中三类有独立风险：

1. **US News 2026 排名**——US News 对排名数据的再分发有明确限制
2. **CMC 撰写的文案**——区位描述 `cz/ce`、气质标签 `tz/te`、一句话点评 `nz/ne`、小文书整理 `essays`、国际生认定摘要 `idef.t`、面试政策摘要 `ivw.t`，都是 CMC 的原创劳动成果
3. **第三方推算值**——`rr` 字段自带标注「(CDS 推算)」，是 CMC 自己算的，不是学校公布值

另有**时效性**：`essays` 里已出现「【26-27 新题已官宣】」「截至 8 月初，以 Common App/官网为准」；`cds_src` 标注 CDS 2024-25 / 2025-26。

**为什么**：事实性数据（录取率、截止日期、标化政策）本身来自学校公开的 Common Data Set，可以用；但**第三方撰写的描述性文案**和**排名数据的再分发**是另外两个法律问题。两者性质不同，不能一起看。

**对用户的影响**：如果产品对外发布，风险落在这三处，不落在功能上。

**怎么改**（三选一，建议 C）：

- **A**：只保留学校公开的事实字段（录取率 / 截止日期 / 标化政策 / 学费 / 经纬度），**删掉全部第三方文案字段**，描述性内容自己重写
- **B**：数据仅用于本次活动现场，不发布、不导出，在文档里写明
- **C（建议）**：**一期按 B 用，二期按 A 替换**。同时把「数据来源与免责说明」写进页脚

## 三、建议改

### S1 · 洞察榜 5 个标签：导向与产品定位不符

**事实**（CMC 源码阈值）：

| 标签 | 阈值 |
| --- | --- |
| 早申倍数高 | 早申录取率 ÷ RD 录取率 ≥ 2.5 |
| 国际生占比高 | 国际生比例 ≥ 15% |
| 转学率较高 | 转学率 ≥ 35% |
| 申请池较小 | 申请人数 < 12,000 |
| 不看标化 | `test === 'blind'` |

**观察**：五个标签全是**申请策略维度**。「申请池较小」和「不看标化」的实际导向是**找更容易进的学校**。实际数据里 `不看标化 9` 就是「加州大学系统 8 所 + 华盛顿大学」——它精准指向一个「免标化」的学校群。

**建议**：一期不做。若要保留，只留「不看标化」并改名为「不要求标化」——它是**事实性信息**。其余三个（申请池较小 / 转学率较高 / 早申倍数高）建议直接去掉：对「方向探索」零贡献，对「钻空子」有明确引导。

### S2 · 收藏与对比位功能重叠

**问题**：方案同时保留「收藏（D1–D4，存浏览器本地）」和「对比位（最多 3 所）」。两者都是「把学校挑出来放着」。

**为什么**：现场家长在**手机**上填问卷、看画像，回家在**电脑**上打开——localStorage 不跨设备，收藏会凭空消失。对比位是会话内的，没有这个问题。

**建议**：一期只保留对比位，砍掉收藏与导出清单；二期若要做收藏，先解决跨设备（写进 URL 或按 token 关联）。

### S3 · 地图点重叠：东北部 57 所挤在一起

**证据**：地区分布 `NE 57 / S 22 / W 18 / MW 16`，覆盖 **30 个州**（20 个州为空）。马萨诸塞 14 所、纽约 13 所、宾州 12 所、加州 15 所。点的半径按排名分档（源码 `rank≤10→6.5 / ≤30→5.5 / 其余→4.6`）——**最大的点正好落在最挤的地方**。

**建议**：保留分档（视觉上确实有用），但缩放超过一定级别时把重叠点散开（spiderfy 或小范围抖动）。原版的「最近点拾取」只解决了「点错」，没解决「看不见」。

### S4 · 表格视图放到二期

**证据**：表格 26 列、三种横向滚动方式、前两列冻结，是给「深度用户」的设计。现场场景是家长排队站着用手机。

**建议**：一期不做表格视图。它是整套功能里最贵、现场使用率最低的一块。

### S5 · 导航有两个坏锚点，动手前先修

**证据**（`HFI-a3e3bf9e/app/page.tsx:25`）：

```tsx
<Link href="#about">关于活动</Link>        // 全文件无 id="about"，点了不跳转
<Link href="#entry">工作人员入口</Link>     // 指向首页的 AI 试用区块，语义不符
```

且导航**硬编码在首页**，`/explore` 与 `/register` 各自写各的 header，没有共享组件。

**建议**：加 `/colleges` 之前先抽出共享导航组件，顺手修掉两个坏锚点。否则第 4 个导航项要同时加到 4 个地方，且继续带着坏链接。

## 四、可以不改

明确写出**没有问题、不需要动**的部分，避免无谓改动：

1. **详情卡 14 节的内容与顺序**（1 排名 / 2 城市州 / 3 学费 / 4 批次 / 5 截止 / 6 录取率 / 7 申请人数 / 8 男女比 / 9 国际生比例 / 10 语言与标化 / 11 面试政策 / 12 小文书 / 13 院校气质 / 14 一句话点评）——与 CMC 逐节核对，顺序一致，无遗漏。
2. **对比表 23 行**——已逐行核对源码 `cmpRows`，与方案列出的 23 行完全一致（不含仅匹配开启时出现的「初步区间」）。每行最优值高亮的取值方向（录取率 / SAT / GPA / 国际生比取最高，申请人数 / 学费取最低）也对。
3. **UI 重组方案 3.1–3.6**——黑表头拆分、图例移出地图、详情浮层改固定侧栏、对比位放侧栏顶部、不做拖拽分隔条、不做横向滑动。这几条理由明确，且都指向「减少浮层遮挡」，方向正确。
4. **技术方案第五节**——离线投影生成静态 SVG、运行时零依赖、不把 d3/topojson 打进客户端。判断正确，与项目「地图必须零外部依赖」的约束一致；坐标可用性已验证（Albers 投影残差最大 0.07 像素）。

## 五、一期范围建议

功能清单共 46 点。若只能保留 40%（约 18 点）做一期，建议保留这些：

| 组 | 保留 | 砍到二期 |
| --- | --- | --- |
| A 地图（10） | A1–A8 全部：底图 / 打点 / 点大小分档 / 缩放平移 / 最近点拾取 / 悬停 / 点选 / 图例 | A10 首次进入提示 |
| B 筛选（8） | B1 搜索 / B2 类型 / B3 地区 / B7 计数 / B8 清除 | B4 批次 / B5 标化政策 / B6 排名（加之前先按 M5 动态化） |
| C 洞察榜（5） | 全部砍掉 | 见 S1 |
| D 收藏（4） | 全部砍掉 | 见 S2 |
| E 表格视图（4） | 全部砍掉 | 见 S4 |
| F 对比（4） | F1–F4 全部 | — |
| G 全局（3） | G3 回到顶部（长页面必需，成本近零） | G1 中英切换 / G2 字号三档 |
| H 黑马匹配（8） | 按已确认的决定保留，但**去掉全部转化话术**（见 M2） | — |

**这样砍的理由**：一期要回答的是「美国有哪些学校、都在哪儿、各是什么样的」。A 组（看得见）+ B 组（找得到）+ 详情卡（看得清）+ F 组（比得了）就够了。C / D / E / G 四组共 16 点，都不服务于这个问题。

**一处需要留意的张力**：C 组（洞察榜）和 H 组（黑马匹配）是本页唯一两块「诱导申请策略」的功能。C 组删掉不损失任何「方向探索」能力；H 组已决定保留，风险只在此备案。
