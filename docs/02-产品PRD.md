## 1. 产品概述

### 1.1 一句话定义

一款**面向家长的 C 端产品**：家长用 3 分钟，通过「自己填写」或「工作人员访谈录入」两条路径之一，看见孩子的**成长方向**——他喜欢和擅长的东西，指向哪些可能的方向，而这些方向在世界上通向哪里。所有孩子的方向汇聚起来，在现场大屏的美国地图上呈现出一张分布图。

**重心是成长探索，不是升学规划。**

### 1.1.1 产品的核心链条（最重要的一张图）

```
孩子的兴趣 / 特质 / 自述
          ↓
   成长方向 Direction          ← 产品真正在讲的东西
          ↓
  这个方向在世界上通向哪里      ← 让抽象的方向变得看得见
    · 对应的美国本科专业            Game Design · Interactive Media
    · 这些方向通向的院校            USC · NYU · RISD · SCAD
    · 未来几年可以走的路            视觉表达 → 原型 → 作品集
          ↓
   美国地图上的一张分布图        ← 让"方向"变成可以被看见的东西
```

**关键判断：院校和专业不是"要去考的目标"，而是"这个方向在现实世界里的样子"。**

家长看到的不是一张报考清单，而是——原来我孩子喜欢的东西，在世界的那一头有人在做，有地方可以学，有路可以走。

少了院校和专业这一环，产品就退化成"给孩子的性格写一段好听话"；
但如果把院校当成报考目标来呈现，产品就变成了中介工具，也就丢了"成长探索"这个立足点。

### 1.1.2 措辞边界

产品要给足**具体、可查**的信息（专业名、院校名、路径），但既不判定孩子，也不做申请定位：

| 不做 | 要做 |
| --- | --- |
| "你的孩子应该去 USC 学游戏设计" | "Game Design 是一个可以去探索的方向，USC / NYU / RISD 都有相关的本科专业" |
| "升学规划" / "申请方案" | "成长方向探索" |
| "目标院校" | "这个方向对应的院校" |
| "冲刺校 / 匹配校 / 保底校" | "高度契合 / 值得了解 / 可以看看" |
| "匹配度 92 分" | "高度契合 · 值得重点了解" |
| "AI 判定" | "基于孩子这次分享的兴趣与特质" |

给足信息、不给结论——这是教育产品的通行做法，也是这个产品能长期存在的前提。

### 1.2 两条用户路径

这是本产品的核心结构，**两条路径都是一等公民，都要做完整**：

```
【路径 A】家长自助填写                    【路径 B】工作人员访谈录入
  手机扫码 / 链接 / 首页按钮                /entry（需访问口令）
         │                                        │
  结构化表单 + chips + 1 个开放题          粘贴访谈原文 → AI 抽取 → 人工核对
         │                                        │
  即时轻画像 + 短码                         保存成功 + 短码（转交家长）
         └────────────────┬───────────────────────┘
                          ▼
              统一数据表 / 同一 AI 引擎 / 同一份画像
```

两条路径的产出必须完全一致，只有数据来源和信息密度不同。

### 1.3 要解决的四个问题

| 问题 | 现在怎么做 | 做完之后 |
| --- | --- | --- |
| 家长知道孩子喜欢画画，但说不清这是一个什么方向、能走到哪里 | 只能去问中介，或者自己瞎搜 | 看见一条从兴趣 → 方向 → 专业 → 院校 → 路径的完整线索 |
| 家长填完表就结束了，什么也拿不走 | 发一张海报、一份伴手礼 | 拿到一份属于自己孩子的成长探索画像 |
| 现场 100 份访谈内容散落在纸笔和微信里 | 事后人工整理，丢一半 | 两条路径即时入库，字段结构化 |
| 主办方办完活动什么都没留下 | 只剩照片 | 一份可复用的数据资产 + 活动报告 |

### 1.4 价值主张

- **对家长**：*"我看见了我的孩子，也看见了他可以去的地方"* —— 孩子的一个兴趣，被翻译成 3 个方向，以及这些方向在世界上通向哪里。
- **对主办方**：*"我们把这场活动变成了一张孩子的成长地图"* —— 现场大屏把上百个孩子的方向在美国地图上铺开，活动后有报告可交付。
- **对孩子**：**给方向，不给结论** —— 不判定他该成为谁，但把世界上的可能性指给他看。

### 1.5 范围

**一期做**

- 家长自助填写路径（零注册）
- 工作人员访谈录入路径（含 AI 文本结构化）
- AI 成长方向分析 + **方向对应的美国本科专业与院校推荐**（单条触发 + 降级；一期不建院校-专业库，由 AI 直接推荐）
- 配一张院校坐标表供地图打点（美国教育部官方数据源全量导入，2,210 所 4 年制/研究生院校）
- 孩子成长探索画像 + 短码回看（含**个体词云**与**个体院校地图**）
- 现场大屏：**方向对应的美国院校地图**、梦想院校地图、方向与专业统计、特质词云
- 首页

**一期不做**

- **任何管理页面**——当前没有运营角色，不为主办方做后台。产品就是家长端、工作人员端、画像页、大屏、首页这五个页面
- **院校-专业库建设**——不做专业字典，不做院校-专业关联，不逐校核对
- 批量导入**孩子数据**（Excel / CSV）、批量勾选操作、批量重跑
- 家长账号体系（手机号 / 微信登录）
- 社区、动态流、公开可浏览的个体画像
- 在线支付、报名费
- 采集真实姓名、手机号、身份证、人脸照片

> 说明：一期没有账号体系，家长凭提交成功后获得的一次性短码回看画像。
> 这在活动场景下是正确的取舍——让家长注册会直接砍掉一半转化。账号留到二期做长期运营时再引入。

### 1.6 规模与前提假设

| 项 | 假设 |
| --- | --- |
| 参与儿童数 | ≤ 100 人 / 场 |
| 活动形态 | 单场次线下活动，家长手机 + 现场大屏 |
| 并发 | 5 分钟窗口内约 100 次表单提交 |
| 路径占比 | 家长自填为主（约 70%），工作人员访谈为辅（约 30%） |
| 语言 | 字段以英文存储，界面中英双语，大屏以英文为主 |

## 2. 用户与核心路径

### 2.1 角色与权限

| 角色 | 入口 | 能做 | 不能做 |
| --- | --- | --- | --- |
| 家长（C 端用户，零注册） | `/register` | 填写并提交；凭短码回看自己孩子画像 | 查看任何其他家庭的数据 |
| 工作人员 | `/entry`（需访问口令） | 录入访谈、AI 抽取、核对保存 | 删除数据、改配置 |
| 现场观众 | `/explore` | 只看聚合结果 | 看到任何姓名与个体信息 |

> **没有运营角色。** 一期不为主办方做管理后台，产品只有上面三个面向使用者的入口。
> 工作人员入口用**共享访问口令**（配置在环境变量里），不做账号体系。
> 我们自己开发期看数据、查问题，直接访问数据库即可——那是内部工作方式，不是产品功能。

### 2.2 两条路径的对比

| 维度 | 路径 A：家长自助 | 路径 B：工作人员访谈 |
| --- | --- | --- |
| 使用者 / 设备 | 家长 / 手机 | 工作人员 / 电脑或平板 |
| 入口 | 二维码、分享链接、首页按钮 | `/entry`，需访问口令 |
| 输入方式 | 结构化表单 + chips + 1 个开放题 | 粘贴访谈原文，AI 抽取成字段 |
| 目标耗时 | ≤ 90 秒 | ≤ 30 秒 / 人（不含访谈时间） |
| 数据特点 | 字段规整，信息密度低 | 信息密度高，需要人工核对 |
| 即时反馈 | 轻画像 + 短码 | 保存成功 + 短码（可打印/转交） |
| 典型场景 | 家长在座位或排队时自己填 | 访谈位、家长不便操作、补充采集 |
| 落库标识 | `entry_path = 'self'` | `entry_path = 'staff'` |

### 2.3 核心用户故事

**家长（路径 A）**
> 我扫码打开页面，看到"与孩子，共成长"。我填了孩子的英文名、年龄、想去的三所学校和一句话，点提交。
> 页面立刻告诉我：Evan 的关键词是 Curious · Creative · Expressive，完整画像正在生成，凭这串短码可以回看。我截图存了下来。

**工作人员（路径 B）**
> 我和家长聊了 5 分钟，把他的话原样粘进录入框，点"AI 整理"，系统把内容拆成了兴趣、优势、性格、梦想职业。我核对一下，点保存，把屏幕上生成的短码念给家长，下一个。

**观众（看大屏）**
> 大屏上先是一个问题："Where are they heading?"，六个方向像扇形一样展开。
> 下面写着 "Where do these paths lead?"，一张美国地图上亮起一个个光点。
> 我点了加州那个最大的光点——University of Southern California，12 个孩子的方向通向这里，游戏设计、交互媒体、影视。
> 切到"梦想院校"图层，还能看到哪些学校孩子心里想着、但方向还没走到的。
> 最下面是词云，中间那个词特别大：Curious。

### 2.4 时间轴与状态机

```
【活动前】                 【活动当天】                        【活动后】
坐标表/词库/方向体系就绪      路径A 扫码填写 ─┐                 数据导出
二维码分发                  路径B 访谈录入 ─┴→ 轻画像(即时)     活动报告
小范围试填                        ↓                           家长回看（凭短码）
                            AI 深度分析（单条异步）              二次传播
                                  ↓
                           大屏每 30 秒更新
```

儿童数据状态机：

```
draft ──提交──→ submitted ──触发分析──→ analyzing ──成功──→ analyzed
                    │                        └──失败──→ analyze_failed
                    │                                   （记录保留、不阻塞展示，
                    │                                     家长端走降级文案）
                    └─ 路径 B 保存后直接进入 submitted
```

## 3. 功能需求

> 优先级：P0 = 一期必须完成；P1 = 现场效果关键；P2 = 交付加分项。

### 3.1 【路径 A】家长自助填写 `/register` — P0

**目标：** 家长零学习成本，90 秒内完成提交，弱网也不丢数据。

#### 3.1.1 表单字段

| 顺序 | 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 知情同意 | 勾选 | 是 | "我同意本次活动收集并匿名展示孩子的成长信息" |
| 1 | 孩子的英文名 | 文本（≤ 20 字） | 是 | 提示"用平时称呼的英文名即可，不需要真实姓名" |
| 2 | 年龄 | 数字选择（6–18） | 是 | 滚轮/按钮，不用键盘输入 |
| 3 | 梦想院校 | 自由文本 × 3 | 是（至少 1 个） | 家长自己填，输入时实时联想坐标表内的院校 |
| 4 | 兴趣方向 | 多选 chips（≤ 3 个） | 否 | 降低填写成本 |
| 5 | 孩子最近最投入的一件事 | 文本（≤ 200 字） | 是 | 唯一必答的开放题 |
| 6 | 如果不考虑现实，孩子最想成为什么 | 文本（≤ 100 字） | 否 | 高信息量，鼓励填 |
| 7 | 家长眼中的孩子 | 文本（≤ 200 字） | 否 | 供 AI 参考 |

#### 3.1.2 院校填写交互（自由输入 + 实时联想）

院校由家长**自己填**，不提供下拉清单。理由：下拉清单会把所有人往少数几所名校上推，
也会让"孩子想去哪"这件事变成一个选择题，失了本意。自由输入更真实，也更有信息量。

```
孩子想去美国的哪所学校？（最多填 3 个，至少填 1 个；实在想不出可以填"还没想好"）

  第一志愿   [ Stanford University              ]
               └ 打字时实时联想：Stanford University · 斯坦福大学
  第二志愿   [ 还没想好                           ]
  第三志愿   [                                   ]

  为什么想去？（选填，一句话）  [________________]
```

**关键：自由输入 + 实时联想**

- 家长打任意文字（中英文、简称、别名都可以）；
- 输入 2 个字符后，下方实时提示坐标表中匹配的院校，点一下即选中；
- 联想只是提示，不强迫家长从清单里选。

**写入时的归并规则**

| 情况 | 处理 |
| --- | --- |
| 家长点选了联想结果 | 直接写入 `canonical_name` + 坐标，可上图 |
| 家长自己打完没点联想 | 服务端按别名做一次匹配，命中则补上 `canonical_name` + 坐标 |
| 匹配不上 | 原文存进 `raw_text`，不上图；**不阻塞提交，也不影响主地图** |
| 家长填"还没想好 / 不确定" | 记为空，不进入统计 |

**为什么不做成下拉框**：下拉框看起来"数据更干净"，但会逼着家长在陌生校名里挑一个，
既增加了填写负担，又让结果失真（所有人都选 Stanford，地图上只剩一个点）。
自由输入 + 系统自动归并，既保住了真实的表达，也能把数据收拾干净。

#### 3.1.3 交互与异常要求

1. 手机优先，单列布局，一屏一个问题，底部固定进度指示；
2. 每步随手保存草稿到 `localStorage`，网络中断后回来能续填；
3. 提交按钮带 loading 与幂等 key，防止重复提交；
4. 提交失败自动重试 3 次；仍失败则提示"已保存在本机，请让工作人员协助录入"，并展示草稿码；
5. 提交成功后立刻展示**轻画像**（见 3.4.5），再展示短码；
6. 全程不采集真实姓名、手机号、微信、身份证、照片。

#### 3.1.4 验收标准

- [ ] 3G 弱网下能完成提交，或给出可恢复的失败提示；
- [ ] 断网填写 → 关闭页面 → 重开，草稿仍在；
- [ ] 连点提交 5 次，数据库只产生 1 条记录；
- [ ] 375px 宽度下无横向滚动、无元素遮挡；
- [ ] 首次使用者无需任何指引即可独立完成提交。

### 3.2 【路径 B】工作人员访谈录入 `/entry` — P0

**目标：** 让工作人员在 30 秒内，把一段访谈原文变成结构化数据。

#### 3.2.1 流程

```
英文名 + 年龄（必填）
      ↓
粘贴访谈原文（不限长度）
      ↓
[ AI 自动整理 ]
      ↓
右侧出现可编辑字段：梦想院校 / 兴趣 / 优势 / 性格 / 梦想职业 / 关键原话
      ↓
人工核对 → [ 保存并继续下一位 ]
      ↓
屏幕显示该孩子的短码（可打印 / 念给家长）
```

#### 3.2.2 要求

1. AI 整理只做**抽取**，不做评价、不生成方向建议（方向建议在保存后统一生成）；
2. 抽取出的字段必须能映射回路径 A 的表单字段（见 4.2 字段对照）；
3. 抽取失败时原文完整保留，允许手工填写全部字段；
4. 保存后进入与路径 A 完全相同的数据表，`entry_path = 'staff'`；
5. 支持"保存并继续"，全流程可用键盘完成；
6. 进入前需要输入**共享访问口令**（不做账号体系）；保存时记录操作人姓名（下拉选择，便于追溯）；
7. 保存后自动触发 AI 分析，无需工作人员额外操作。

#### 3.2.3 验收标准

- [ ] 一段 300 字访谈原文，AI 抽取响应 ≤ 8 秒；
- [ ] 抽取结果可逐字段修改，保存的是人工确认后的结果；
- [ ] 保存后大屏人数 +1，且该条记录能在 `children` 表中查到（`entry_path = 'staff'`）；
- [ ] 短码在保存成功后清晰可见，便于当场转交家长。

### 3.3 孩子成长画像与回看 `/child/[token]` — P0

未来 3–5 年   12–14 培养视觉表达 → 15–16 学引擎做原型 → 16–17 作品集

免责说明：本结果基于本次活动中的兴趣与回答，用于成长方向探索，
不构成专业测评、录取预测或任何形式的判定。
```

**每个孩子的画像包含四块内容，缺一不可：**

| 模块 | 作用 | 说明 |
| --- | --- | --- |
| 我们看到的他 / 她 | **对孩子的理解** | 2–3 句，从孩子自己的话里长出来，不是通用夸赞 |
| 个体词云 | **把理解视觉化** | 8–12 个词，按重要程度呈现大小差异 |
| 方向卡片 ×3 | 方向 → 专业 → 院校 | 三个层次递进指向 |
| 个体方向地图 | **把方向落到地理上** | 这个孩子的院校落点，可点击 |

**每个方向下必须有三个层次，缺一不可：**

| 层次 | 内容 | 数据来源 |
| --- | --- | --- |
| 方向 | Game Design | AI 从固定分类体系中选择 |
| 专业 | Game Design / Interactive Media | AI 推荐，标准英文名 |
| 院校 | University of Southern California · New York University · Rhode Island School of Design | AI 推荐大学名（不含学院名），带契合层级与理由 |

三个层次的关系是**递进指向**，不是报考清单：
「孩子喜欢这个 → 这是一个可以探索的方向 → 这个方向在世界上通向这些地方」。

院校条目必须可点击 → 在地图上定位到该院校，看到它对应的专业和推荐理由。

#### 3.3.2 硬性要求

1. 访问凭证使用随机 token（≥ 16 位），**禁用自增 ID**；
2. 页面 `noindex`，不生成分享卡片；
3. 文案必须给足信息（专业名、院校名、路径），但不得出现"适合 / 判定 / 建议选择 / 录取概率 / 冲刺 / 保底"；
4. 移动端优先（家长几乎一定在手机上打开）；
5. AI 尚未完成时显示"画像正在生成，稍后回看"，不显示空白或报错；
6. 短码入口要足够简单：家长可以只输短码，也可以直接点链接；
7. **院校卡片必须能跳转到地图并定位**，这是"方向 → 专业 → 院校 → 地理位置"这条链路的闭环；
8. **院校只显示大学名，不显示学院名**；每个院校条目旁必须有官网搜索链接和"以官网为准"的说明；
9. **个体词云与群体词云使用同一套词库**，只是口径不同（个体是权重、群体是频率）；
10. 个体地图与现场大屏地图**共用同一套数据和渲染组件**，不做两套实现。

#### 3.3.3 验收标准

- [ ] 用错误 token 访问返回 404，不泄露记录是否存在；
- [ ] 完整画像在手机上无需横向滚动即可读完；
- [ ] AI 未完成 / 已完成 / 失败三种状态下页面都不白屏；
- [ ] 点击任意院校卡片能跳转并定位到地图上的该院校；
- [ ] 抽查 20 条画像，院校名都是真实存在的美国大学，且**没有学院名**；家长点搜索链接能查到对应专业；
- [ ] 个体词云在手机上清晰可读，最多的词与最少的词有明显大小差异；
- [ ] 个体地图的落点数 = 命中坐标表的推荐院校数（未命中的只在列表里，不上图，且有明确提示）。

### 3.4 AI 分析引擎 — P0

#### 3.4.1 分析流程（单条触发）

**一次调用产出全部内容**：对孩子的理解、特质、3 个方向、每个方向对应的美国本科专业与推荐院校。

```
child 数据落库（路径 A 提交 / 路径 B 保存）
      ↓
组装 Prompt（孩子信息 + 方向分类体系 + 特质词库 + 推荐规则）
      ↓
调用 DeepSeek（服务端，OpenAI 兼容 Chat Completions）
      ↓
Schema 校验
  · 方向在 7 大类体系内
  · 特质在 62 词词库内
  · 字段齐全、JSON 可解析
      ↓
通过 → 落库 ai_analyses + school_recommendations，status = analyzed
      ↓
用本地坐标表给院校打点（命中打点，未命中只进列表）
不通过 → 自动重试 1 次 → 仍失败 → analyze_failed（记录保留）
```

> 一期不做批量处理：每条数据独立触发、独立重试。
> 失败记录完整保留（含原始输入与错误信息），活动前统一重跑，不做批量操作界面。

#### 3.4.2 推荐层级定义

| 层级 | 展示文案 | 含义 | 用途 |
| --- | --- | --- | --- |
| `strong_fit` | 高度契合 | 孩子的兴趣特质与该专业高度吻合，且该校该专业实力突出 | 重点了解 |
| `good_fit` | 值得了解 | 方向吻合，学校资源匹配 | 可以了解 |
| `explore` | 可以看看 | 相关但非直接对口，作为视野拓展 | 打开思路 |

刻意**不使用"冲刺 / 匹配 / 保底"**这一套申请术语——那是中介话术，会把这个产品拖进"录取预测"的雷区。

#### 3.4.3 硬性约束

1. **只能在服务端调用**：浏览器 → Next.js API Route → DeepSeek，API Key 只存在于服务端环境变量；
2. **必须返回 JSON**，且必须通过 Schema 校验才入库；
3. **方向必须来自固定分类体系**（见 5.1），不得自由发挥新专业名；
4. **特质必须来自固定词库**（见 5.2），每个孩子 8–12 个；
5. 记录 `model`、`prompt_version`、`latency_ms`、`raw_response`，便于回溯；
6. 切换 Prompt 版本后可对单条重跑做对比；
7. **院校与专业由 AI 直接推荐**（一期没有院校库），但要受 Prompt 严格约束（见 5.4）：
   只写大学名称，不写具体学院名；院校与专业用标准英文名；
8. 推荐结果解析后落 `school_recommendations` 表，地图与统计只读这张表，不解析 JSON；
9. 落库前做一次**校名归一化**（大小写、缩写、别名），保证同一所学校只有一个写法，否则地图上会散成多个点。

#### 3.4.4 并发与限流

| 场景 | 策略 |
| --- | --- |
| 单条提交后 | 立即异步触发，不阻塞家长页面 |
| 集中提交 | 服务端限并发 3–5，其余排队；大屏不依赖 AI 完成即可显示统计 |
| 超时 | 单条超 30 秒判定超时，自动重试 1 次 |
| 限流 | 指数退避重试；仍失败记为 analyze_failed |

#### 3.4.5 降级方案（必须实现）

AI 挂了，活动不能停：

- 规则引擎先用关键词映射出 category 与 traits，保证大屏统计永远有数据；
- 家长看到的轻画像（提交后 0.5 秒内）不依赖 AI：

```
我们收到了 Evan 的探索卡

关键词：Curious · Creative · Expressive
梦想方向：Arts & Design

完整画像正在生成，稍后可凭短码回看
```

- 单孩子画像在 AI 未完成时显示"生成中"，AI 恢复后自动补跑并更新；
- 分析失败的记录完整保留（含原始输入与错误信息），可事后重跑；
- **地图不能空**：AI 失败时，先用规则把该方向下的默认院校写入 `school_recommendations`，
  保证地图上仍然有内容；AI 恢复后重跑并覆盖为正式结果。

- [ ] 连续提交 100 条，AI 分析成功率 ≥ 95%；
- [ ] 人为断开 API Key，系统降级后大屏与轻画像仍正常，活动可继续；
- [ ] 数据库中不存在方向或特质超出体系 / 词库的记录；
- [ ] 家长页面在 AI 未完成时不会被阻塞；
- [ ] 抽查 20 条推荐结果，院校名都是真实存在的美国大学，且不含学院名；
- [ ] 单条完整分析（理解 + 词云 + 方向 + 推荐）耗时 ≤ 20 秒。

### 3.5 现场探索大屏 `/explore` — P1

> 它不是一个需要专门设备的"大屏系统"。现场做法就是：用场馆的屏幕 / 电视 / LED 屏，
> 浏览器全屏打开这个网址。所以我们只需要保证这个页面在"当显示器用"这个场景下够用。

#### 3.5.2 两张地图的区别（必须分清）

> 本节只讲两张地图在 PRD 层面的关系。**气泡算法、归一化规则、聚合、动效、数据接口、完整草图，
> 见 `docs/03-地图模块需求方案.md`。**

| | 方向地图（主） | 梦想院校地图（辅） |
| --- | --- | --- |
| 英文标题 | Where do these paths lead? | Where are they dreaming of? |
| 数据源 | `school_recommendations`（AI 从兴趣特质推出来的方向落点） | `children_universities`（家长自己填的志愿） |
| 性质 | 系统从孩子的兴趣与特质推出来的 | 孩子自己心里想的 |
| 光点含义 | 有 N 个孩子的方向通向这里 | 有 N 个孩子把这里填成志愿 |
| 价值 | **回答"这些方向在世界上通向哪里"** | 反映向往，制造话题 |
| 优先级 | P1，必做 | P1，可延后 |

> 梦想院校是家长**自由填写**的，校名没命中坐标表的就不上图，但原文不会丢失（存在 `raw_text`）。
> 主图层用的是 AI 推荐结果，不受家长填写的准确度影响——这也是把主图层放在方向数据上的一个额外好处。

**叠加模式（推荐做，效果最好）**

两个图层同时打开时，可以讲出一个很有洞察力的故事：

- 某校梦想人数远多于方向人数 → "很多孩子心里想着这里，但他们的方向还没走到这里"；
- 某校方向人数多但没人填 → "孩子们还没听说过这个方向可以通向这里"；
- 两者高度重合 → "有一批孩子的方向已经很清楚了"。

这会在现场产生真实的讨论，是大屏从"装饰"变成"内容"的关键。

#### 3.5.3 要求

**因为"它只是一个网址"，这几条反而是硬要求：**

1. **打开即用，不需要登录、不需要口令、不需要任何前置操作**——现场谁拿到网址都能打开；
2. **网址要好念好输**（用同一个域名下的短路径，别出现一长串参数）；
3. **自适应屏幕**：不写死分辨率。笔记本、显示器、电视、LED 屏都能铺满，横屏优先，
   同时兼顾手机（家长可能自己打开看，布局自动简化）；
4. **自动刷新**：每 30 秒自己更新，刷新不闪屏、不重置图层和选中的院校——不能指望有人守着按 F5；
5. **断网自恢复**：网络抖一下之后能自己回到最新状态，不白屏、不需要手动刷新；
6. **能连开一整天**：无人值守也不会卡死或内存泄漏。

**内容要求：**

7. 默认展示**方向图层**，梦想院校作为可切换图层；
8. 数据为空时显示友好占位（"探索即将开始"），不显示 0 或空白；
9. **不得**出现任何孩子的英文名或个体画像；
10. 地图交互：hover 显示、点击展开该院校的方向人数、专业分布、年龄分布；无人操作 20 秒后自动轮播人数最高的院校；
11. 同城院校光点重叠时自动做聚合（如 Boston / Los Angeles），展开后显示具体院校；
12. 方向与专业统计只读 `school_recommendations`，按 `direction` / `program_name` / `category` 三个口径各出一版；
13. 词云使用固定词库，字号随词频，最大词不小于最小词的 4 倍；
14. 地图底图与院校坐标全部本地打包，不依赖实时 CDN。

## 4. 数据模型

### 4.1 实体关系

```
events ──< children >
              │
              ├──< children_universities        ← 梦想院校（家长自己填的原文）
              │
              ├──< ai_analyses >── trait_selections >── traits（62 词特质词库）
              │        │
              │        └──< school_recommendations >  ← AI 推荐的院校 + 专业
              │                 （地图与统计的唯一数据源）
              │
              └── 配合一张静态坐标表 data/university_coords.csv 做地图打点
```

**一期不建院校-专业库。**

院校和专业由 AI 直接推荐，不做候选池、不做专业字典、不做院校-专业关联。
这样一期省掉了 8–15 人日的逐校核对工作，代价是推荐结果的准确度依赖模型能力，
需要用 Prompt 约束和文案兜底来控制（见 5.4）。

但地图打点必须有坐标，所以保留**一张轻量的院校坐标表**：

| 数据 | 形式 | 作用 | 规模 | 工作量 |
| --- | --- | --- | --- | --- |
| `university_coords` | `data/` 下的 CSV，打进代码，不入库 | 校名 → 经纬度，供地图打点 | 2,210 所 | 半天 |

> 这张表只需要「校名 / 别名 / 州 / 经纬度」五列，不需要专业信息。数据来自美国教育部官方数据源
> College Scorecard（全量 6,273 所院校，每条都带经纬度），**不是"院校-专业库"**。
> 命中就打点，没命中的院校仍然出现在画像的推荐列表里，只是不落在地图上。

当前只有一场活动，但保留 `events` 表，明年复用时不改代码只加数据。

### 4.5 数据建设（一期只有三张表）

一期不建院校-专业库，需要准备的只有下面三张表：

| 数据集 | 规模 | 来源 | 工作量 |
| --- | --- | --- | --- |
| **院校坐标表** `university_coords.csv` | **2,210 所** | 美国教育部 College Scorecard，官方 CSV 全量下载后过滤 | **半天** |
| 特质词库 `traits.csv` | 62 个词 / 4 组 | 本 PRD 5.2 已给出，直接落表 | 0.5 人日 |
| 方向分类体系 `directions.csv` | 7 大类 + 二级方向 | 本 PRD 5.1 已给出，直接落表 | 0.5 人日 |

坐标表只需要五列：`name, aliases, state, latitude, longitude`。
它不承担推荐逻辑，只负责把 AI 推荐出来的校名翻译成地图上的一个点。

**为什么是全量导入，而不是人工挑 200 所**：一开始估的是"人工整理 150–200 所主流院校"，
核实官方数据后这个估算反了——**全量导入比人工挑选更省事，覆盖率还更高**。
官方名录里有 6,273 所院校，取其中的 4 年制本科与研究生院校（2,210 所）全量导入即可。
去掉职业学校（2,619 所）是为了避免归一化产生假匹配。

> 坐标表的导入规则、字段映射、别名维护方式和已知局限属于地图模块的实现细节，
> 记在 `docs/03-地图模块需求方案.md` 4.1。本文档只保留产品层面的取舍判断。

**关于准确度**：一期把准确性交给 Prompt 约束 + 文案兜底，不再承担逐校核对的工作量。
具体做法见 5.4，包括：

- 院校只写大学名称，**不写具体学院名**（省掉最容易出错的部分）；
- 推荐时优先给广为人知、确定性高的院校；
- 画像页加一句"具体专业设置以学校官网为准"，并提供官网搜索链接。

> 这是一个明确的取舍：**用一点准确度风险，换掉 8–15 人日的数据核对工作。**
> 如果活动后要做成长期产品，再把院校-专业库补上，那时 `school_recommendations`
> 的历史数据还能反过来当成建库的素材。

          "program_name": "Game Design",

          "match_level": "strong_fit",

        }
      ]
    }
  ],
  "strengths": ["视觉表达", "叙事能力"],
  "watch_points": ["需要持续的作品输出"],
  "next_steps": [
    { "age_range": "12-14", "action": "培养视觉表达与故事叙述" },
    { "age_range": "15-16", "action": "接触游戏引擎，做小型原型" },
    { "age_range": "16-17", "action": "完成个人作品集" }
  ],
  "disclaimer": "本结果为基于本次活动回答的成长方向探索，不构成专业测评、录取预测或任何形式的判定。"

```

**关于院校推荐的三条硬规则（写进 Prompt）**

1. **只写大学名称，不写具体学院名**——"University of Southern California" 而不是 "USC Games"。
   学院名是最容易出错的部分，也是家长最不容易核实的部分，去掉它准确度会明显提升。
2. **只推荐广为人知、确定性高的院校**，不确定的宁可不写；每个方向 3–5 所。
3. **专业名用标准英文名**（Game Design / Computer Science / Psychology），不要自造复合专业名。

AI 不需要返回经纬度——坐标由服务端在分析完成后，用本地坐标表按校名统一补写。

**关于 `traits` 与词云**

- `traits` 按**重要程度降序**返回 8–12 个，全部来自固定词库（见 5.2）；
- 系统按位置赋权：第 1–2 位权重 5，3–4 位 4，5–6 位 3，7–8 位 2，9–12 位 1；
- **个体词云按权重渲染字号，群体词云按出现频率渲染字号**；
- 两者共用同一套词库，所以口径永远对得上，不会出现"个人的词和群体的词不是一套"的问题。

**字段说明**

| 字段 | 说明 |
| --- | --- |
| `understanding` | 画像页第一屏的内容，家长最先看的部分 |
| `traits` | 8–12 个并排序，撑起个体词云 |
| `programs` | 该方向对应的美国本科专业（标准英文名） |
| `recommended_schools` | 院校推荐：大学名 + 专业名 + 州 + 推荐层级 + 理由 |
| `match_level` | 三档：高度契合 / 值得了解 / 可以看看（替代分数，也避开申请定位话术） |
| `reason` | 家长真正会看的部分，也是"给路径不给结论"的体现 |

### 5.4 Prompt 边界（写进 System Prompt）

**必须遵守**

1. 只使用孩子和家长提供的原话作为依据，不臆测家庭背景、经济条件、成绩或种族；
2. 输出 3 个方向，按可能性排序，每个都要给出具体理由；
3. 语言风格：鼓励、具体、克制。不使用"天赋""注定""最适合""必须"；
4. 禁止出现"诊断""测评""判定""筛选""适合性结论"等表述；
5. 特质只能从给定词库中选，8–12 个，按重要程度降序；
6. 方向只能从给定分类体系中选；
7. 路径 B 的输入是访谈原文，需从中区分**孩子原话**与**家长评价**，两者权重不同；
8. **院校只写大学名称，不写学院名、研究中心名、项目代号**；专业用标准英文名；
9. **只推荐你确定存在的院校与专业组合**，优先广为人知、确定性高的院校；不确定的一律不写，每个方向 3–5 所；
10. 推荐理由必须落到孩子的具体表达上，不能是"该校资源优秀"这类通用描述；
11. 不得预测录取结果、不得暗示录取概率、不得使用"冲刺 / 匹配 / 保底"话术；
12. 只输出 JSON。

**反例（不允许）**
> 这个孩子非常适合学游戏设计，建议尽早确定专业方向。

**正例（期望）**
> Evan 反复提到"想把脑子里的画面做出来"，并且喜欢设计关卡。Game Design 是他可以先去探索的一个方向：
> 它同时用到视觉表达与结构思考，而 University of Southern California 与 New York University
> 都在这个方向上提供了成熟的本科路径。

**关于准确度的兜底（因为一期没有院校库）**

Prompt 约束能减少出错，但消除不了。所以在产品层面加三道兜底：

1. **不写学院名**——去掉最容易出错、家长又最难核实的那一层；
2. **画像页加一行小字**："院校与专业信息仅供参考，具体专业设置请以学校官网为准"；
3. **院校名旁给一个搜索链接**（点一下跳到官网搜索），让家长能自己核实。

这三条加起来成本很低，但能把"AI 说错"从"产品翻车"降级成"家长多查一次"。

### 5.5 成本与性能预估

| 项 | 估算 |
| --- | --- |
| 单次分析输入 | 约 1200–1800 tokens（含方向体系与特质词库） |
| 单次分析输出 | 约 900–1400 tokens（含 3 个方向与院校推荐） |
| 100 个孩子总计 | 约 30 万 tokens（量级很小，成本可忽略） |
| 单条耗时 | 10–20 秒 |
| 并发策略 | 3–5 并发，100 条约 10–15 分钟完成 |

结论：**AI 成本不是问题，稳定性和推荐的可信度才是**。
本模块的重点是两件事：单条异步 + 降级方案，以及用 Prompt 约束压住推荐出错率。

## 6. 页面结构与视觉规范

### 6.1 路由表

```
/                    首页：两条路径入口 + 实时数据摘要
/register            路径 A：家长自助填写
/register/success    提交成功：轻画像 + 短码
/entry               路径 B：工作人员访谈录入（需访问口令）
/child/[token]       孩子成长画像（凭短码）—— 产品的价值交付页
/explore             现场大屏（地图 / 统计 / 词云）

一共五个页面，没有管理后台，也没有其他入口。
```

### 6.2 视觉方向

- 主色：深绿 / 墨绿；辅色：米白；点缀：半透明玻璃质感；
- 关键词：高级、克制、自然、有空间感。参考高端教育与艺术机构，不参考互联网产品；
- 避免：大面积渐变、卡通插画、过度圆角、发光霓虹；
- 字体：英文标题用衬线体（Fraunces / Playfair）增强质感，正文用无衬线（Inter）；
- 家长端：温暖、清晰、一屏一件事；
- 大屏：信息密度低，字号大，留白足，深浅对比明确。

> 视觉必须在功能与数据跑通之后再打磨——先做对，再做好看。

| 数据安全 | RLS + 服务端鉴权；access_token 随机不可枚举；密钥只在服务端 |
| 合规 | 家长知情同意；数据最小化；不采集身份信息；提供数据删除通道 |
| 兼容 | iOS Safari 15+、Android Chrome 100+；工作人员端支持 Chrome / Edge |
| 可维护 | 院校坐标表、特质词库、方向分类体系与代码解耦，全部放在 `data/` 下的 CSV 里（由我们维护，不是产品功能），明年换数据不改代码 |

### 8.2 地图方案选型

#### 8.2.1 先说清楚"地图"是什么意思

「TopoJSON 州界图」听起来很技术，其实说的是一张**只有美国各州轮廓的简图**：

```
真实的在线地图（OpenStreetMap）      TopoJSON 州界图
─────────────────────────────       ─────────────────────────────
 · 有道路、河流、地形                 · 只有州的轮廓线
 · 有城市名、地名、POI 图标            · 没有路、没有地名、没有地形
 · 分几十级缩放，边拉边下载瓦片       · 一个约 100KB 的文件，一次加载完
 · 必须联网，向别人的服务器要图        · 完全离线，不打任何外部请求
 · 底图是灰的、有大量细节             · 底色由我们定（米白），只有干净的轮廓
```

两者上面都可以叠加同一批院校光点。**区别只在"底图画什么"，不在"能不能标出学校"。**

`TopoJSON` 是这种地理数据的文件格式（GeoJSON 的压缩版，把相邻州的公共边界只存一次，所以体积小）。`us-atlas` 是公开的美国州界 TopoJSON 数据集，约 100KB，npm 直接装。

#### 8.2.2 关于 OpenStreetMap：我上一版说重了，更正一下

我上一版写"OSM 使用政策不允许"，这个说法不准确。实际上：

- OSM 官方瓦片政策限制的是**批量下载、给瓦片服务器加压、做成 App 大规模分发**；
- 一场活动、100 个用户、4 小时的交互式访问，**并不构成政策意义上的滥用**；
- 真正的风险是下面这三条。

所以准确的说法是：**能用，但不建议用在现场大屏上。** 理由：

| 真实问题 | 说明 | 严重程度 |
| --- | --- | --- |
| **国内访问不稳定** | tile.openstreetmap.org 在国内时通时不通，速度也没保证。现场大屏 4 小时全靠它，等于把最关键的展示压在一个不可控的外部服务上 | **高**（这是主要理由） |
| **视觉噪音** | OSM 默认底图带道路、地名、POI。投到 5 米外的大屏上是一团花。我们要表达的是"这些方向通向美国的哪里"，干净的州界图反而更有力 | 中（设计判断） |
| **政策边界模糊** | 单场活动没问题，但如果这个产品以后要长期运营、要给很多用户用，就必须换成自托管或商业瓦片 | 低（一期可忽略） |

#### 8.2.3 三个方案

| 方案 | 是什么 | 外部依赖 | 大屏效果 | 复杂度 |
| --- | --- | --- | --- | --- |
| **A · 州界图（推荐）** | react-simple-maps + 本地 us-atlas TopoJSON，Albers USA 投影（阿拉斯加/夏威夷缩到左下角） | **无** | 干净、高级、克制 | 低 |
| B · 真实地图 · 自托管 | MapLibre GL JS + 自托管矢量瓦片（如 Protomaps PMTiles 的美国区域切片） | 自托管，可控 | 真实地理质感 | 中 |
| C · 直连 OSM 瓦片 | Leaflet / MapLibre 直接读 tile.openstreetmap.org | 外部，国内不稳 | 嘈杂 | 低 |

**A 的三条理由：**

1. 现场永不白屏是首要目标，A 没有任何外部依赖；
2. 深绿 + 米白的品牌调性下，干净的州界图比真实底图更搭；
3. 我们要表达的是"这些院校分布在哪些州"，不是"怎么开车过去"——州轮廓完全够用，而且文件只有 100KB 左右，手机秒开。

**如果确实想要真实地图质感，走 B 而不是 C。**
做法是下载美国区域的矢量瓦片包，自己托管，既真实又可控，还能离线。
代价是文件体积（取决于缩放级别，可能几十 MB 到几百 MB）和一点额外配置。

**建议的做法：把底图做成可切换的。**
院校光点的数据和交互完全不变，只是底图换成 A 或 B。
开发成本增加很少，但你可以：

- 在活动前，用现场那块屏幕打开两个版本实际比一次，看哪个更好看；
- 万一 A 的效果不够，能立刻切到 B，而不是临时改代码。

实现上很简单：网址后面带一个参数（如 `?basemap=street`），打开就是 B，不带参数就是 A。
不需要后台开关，也不需要改代码。

#### 8.2.4 坐标说明

院校坐标统一用 WGS84（经纬度）。
GCJ-02 偏移只影响中国境内数据，**美国区域的院校坐标不需要任何转换**。
反过来说，用高德 / 天地图这类国内底图去画美国，反而会有数据质量和对齐问题——所以更推荐 A 或 B。

#### 8.2.5 一致性要求

家长端个体地图、首页预览、现场大屏，**共用同一套渲染组件和数据接口**，
只是尺寸和交互模式不同。不做三套实现。底图切换在组件层做，三处同时生效。

### 8.3 部署必须提前决策

Vercel + Supabase 在国内访问不稳定。**现场 100 位家长扫码打不开，就是这个产品最大的单点故障。**

1. 开发阶段仍可用 Vercel + Supabase，速度快；
2. 上线前至少 7 天，用国内手机 4G/5G + 现场 WiFi 实测：首页、扫码页、提交、画像页、大屏；
3. 不达标则改用国内云服务器 + 已备案域名（应用与数据库同区部署）；
4. 无论如何，现场必须保留"工作人员录入"兜底通道，并提前告知主持人。

| 地图依赖外部瓦片服务 | 现场白屏 | 默认用本地 TopoJSON（方案 A），零外部依赖；不用 OSM 官方瓦片 |

| 儿童数据泄露 | 合规与品牌风险 | 三级展示规则 + RLS + 随机 token + 不采集身份信息 |
| 文案越界（"AI 判定孩子未来"） | 家长反感、口碑风险 | Prompt 边界 + 统一免责说明 + 上线前文案评审 |
| 一期无账号，家长找不到回看入口 | 画像打开率低 | 提交成功页强调短码 + 提供截图引导 + 活动后短信/群发补发链接 |
| 首页视觉耗时过多 | 核心功能延期 | 严格按里程碑推进，美化放 M9 |
