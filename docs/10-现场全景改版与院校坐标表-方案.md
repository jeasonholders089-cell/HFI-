## 二、方向分类：4 类 → 8 类

### 2.1 最终定义（单轴：学科领域）

| # | 类别 | 覆盖 | 与旧 4 类的关系 |
| --- | --- | --- | --- |
| 1 | 人文科学 | 文学 / 历史 / 哲学 / 语言学 / 宗教 / 古典学 / 区域研究（人文向） | 保留（旧：人文科学） |
| 2 | 社会科学 | 政治 / 社会学 / 心理 / 人类学 / 国际关系 / 公共政策 / 法律预科 | 保留（旧：社会科学） |
| 3 | **商科与管理** | 经济与金融 / 管理 / 创业 / 市场 / 会计 / 信息系统（商科向） | **拆分自旧「社会科学」** |
| 4 | 自然科学 | 物理 / 化学 / 生物 / 地球与海洋 / 天文 / 环境科学 | 保留（旧：自然科学） |
| 5 | **数学与计算** | 数学 / 统计 / 数据科学 / 计算机 / 人工智能 / 信息科学 | **拆分自旧「自然科学」** |
| 6 | **工程与应用** | 机械 / 电子 / 土木 / 材料 / 生物医学工程 / 航空航天 / 建筑 | **拆分自旧「自然科学」** |
| 7 | 艺术与设计 | 视觉艺术 / 音乐 / 表演 / 影视 / 设计（含工业、交互） | 保留（旧：艺术，加「与设计」） |
| 8 | **健康与公共服务** | 护理 / 公共卫生 / 运动科学 / 教育 / 社会工作 / 公共管理 | **拆分自旧「自然科学」与「社会科学」**（v1.1 把「传媒」移出，见下） |

**刻意不设的两个桶**（与产品决策一起记在这里，避免以后又绕回来）：

- **「跨学科」不做桶**。它是一个「结构属性」，不是一个学科：认知科学既跨学科、又属于自然或社科。让 AI 在两者之间二选一，同一个方向会在不同批次落到不同的桶，**统计不可复现** —— 家长看到隔壁孩子的「认知科学」归了社科、自己的归了跨学科，这屏数字就失去信任。而「跨学科」这件事方向名自己会说出来（认知科学、神经科学、环境研究、媒体艺术与技术都是 AI 起的方向名）。
- **「职业」不做桶**。中文语境里「职业」贴着「职校 / 职业教育」，在大屏上属于**可能被读成降级**的标签；而它想覆盖的那批专业本来都有明确的学科归属：商科 → 第 3 类，护理与教育 → 第 8 类，传媒 → 社会科学或艺术与设计（见下一条），不需要单列。

**v1.1：把「传媒」从第 8 类移出**

第 8 类的轴是**照护与公共服务**——护理 / 公共卫生 / 运动科学 / 教育 / 社会工作 / 公共管理，
这六项有共同轴。而传播学、新闻学在美本语境里归人文 / 社科，影视制作归艺术，
**「传媒」放在"健康与公共服务"里没有共同轴**：家长看到"孩子的方向是传媒 → 落在健康与公共服务"，
第一反应是分类不准，而**一次被看穿的分类错误会打掉整屏统计的可信度**——
这与本节拒绝「跨学科」桶用的是同一条理由。

这次修订**只改判定规则，不动 8 个类别字符串**（数据契约、四处的同步点、库里的类别值都不变），
而且**现在改的成本是零**：`docs/09` §10.2 第 10 条记着库里 4 条记录 `classified = 0`，
**没有任何已分类数据需要重跑**。等活动当天再改，就是几十条记录重跑 + 现场等着。

### 2.2 判定规则（写进 prompt，不得留白）

| 方向语义 | 归入 |
| --- | --- |
| 工程、电子、机械、材料、航空航天、建筑 | 工程与应用 |
| 纯数学、统计、数据科学、计算机、人工智能 | 数学与计算 |
| 偏实现与系统的计算方向 | 工程与应用 |
| 商科、金融、管理、市场营销、会计 | 商科与管理 |
| 护理、公共卫生、运动科学、教育、社会工作、公共管理 | 健康与公共服务 |
| **新闻、传播、媒体研究**（v1.1 新增） | 社会科学 |
| **影视制作、媒体艺术**（v1.1 新增） | 艺术与设计 |
| 设计（含工业设计、交互设计） | 艺术与设计 |
| 认知科学、神经科学、环境研究这类跨领域项目 | 按其**主要学科归属**，不设「跨学科」桶 |

### 2.3 老数据怎么办

`categorized()` 保持**严格**：类别必须在新 8 类里。于是：

- 库里已经分析过、类别还是旧 4 类的记录，会被判为「待分类」；
- 现场全景页上已有「AI 补全分类」按钮（`pendingCategories`），点一次就按新类重跑 —— 已有链路，不需要新写代码；
- `/api/children/analyze` 在发现记录有 3 个方向但类别不合法时，会走「只重分类、不重生成方向」的分支，成本很低。

> **现在改代价最低**（v1.1 补实测依据）：`docs/09` §10.2 第 10 条记着库里 4 条记录
> `classified = 0`，**没有任何已分类数据需要重跑**。等活动当天再改，就是几十条记录重跑 + 现场等着。

### 3.2 地图做什么 / 不做什么

| 做 | 不做 |
| --- | --- |
| 复用选校地图的**底图三层**（海洋 / 邻国陆地 / 美国本土 + AK/HI 插图 + 投影阴影） | 不做缩放、平移、双击 |
| 圆点大小按人数分档，颜色统一 | 不做筛选、搜索、洞察榜 |
| 人数前 **12** 名在地图上挂「校名 · N 人」（v1.1 从 8–10 提到 12，见下） | 不做对比位、不做详情栏 |
| 悬停看「校名 · N 人」（SVG `<title>`，零 JS）——**加分项，不是信息入口** | 不做表格视图 |

> **v1.1 修订（评审 M2）**：「悬停」不能当信息入口。两个理由：
> ① **大屏前面没有鼠标**，而这一页又不做缩放平移，唯一可能用鼠标打开它的是工作人员的笔记本；
> ② 实现上它大概率根本不弹——`components/explore/dream-school-map.tsx` 的 `<circle>`
> 带着 `pointerEvents="none"`（从选校地图照搬来的，那边是让位给平移与最近点拾取），
> **元素不参与 hit-test，原生 `<title>` 就不会触发**。
>
> 因此：① 标签名额 8 → **12**，让地图自己把话说清楚；② 删掉 `pointerEvents="none"`
> （顺手清掉没人读的 `data-school` / `data-count`），让预览时真能悬停；
> ③ 大屏目视的验收标准改成"**不悬停、不点击**也能说出人数最多的 3 所学校与名次"。

底图的三个可复用件已经在 `lib/us-map-paths.ts`（`STATE_PATHS` / `NEIGHBOR_LAND` / `US_INSETS`）。
**要抽出共享组件**：把三层底图从 `components/colleges/colleges-map.tsx` 抽成
`components/map/us-base-layers.tsx`，选校地图与现场全景都用它，避免两处各画一套。
投影函数 `project()` 从 `lib/colleges-project.ts` 抽到 `lib/map-project.ts`
（原文件 re-export，所有现有 import 与测试不受影响）。

### 3.3 口径与隐私（**不可妥协**）

- **不显示任何姓名**。大屏是公开页面，`AGENTS.md` 第五节明令不得出现「孩子姓名 + 个人画像」的组合；
  「谁选了哪所学校」正是那个组合（这也是 `/api/children/summary` 未脱敏那条已知缺口的同类风险）。
- **量词口径（v1.1 新增，评审 M4）**——现在页面上「人」和「人次」用反了，一次说清：

  | 数字 | 口径 | 该用什么量词 | 用在哪 |
  | --- | --- | --- | --- |
  | 单所院校那个数 | 填了它的**孩子数**（同一孩子同校只计一次） | **N 人** | 地图标签、悬停、完整名单 |
  | 跨校合计 | 各校人数相加（同一孩子填 3 所算 3 次） | **N 人次**，并补半句"同一孩子的多所院校各计一次" | 图下那行小字、地图副标题的口径说明 |
  | 方向统计 | 落在该类别的**孩子数**（同一孩子同类只计一次） | **N 人** | 发展方向统计 |

  例：地图标签写 `斯坦福大学 · 3 人`（v1.1 补单位，现在没有单位）；图下写
  「另有 3 人次填了暂未收录的院校（2 所），见下方名单」。
  **验收**：全页 grep `人次`，只允许出现在"跨校合计"的两处。
- **未收录的说法要人话（评审 S4）**：名单里用「暂未收录」，图下用整句
  「另有 N 人次填了暂未收录的院校（M 所），见下方名单」——"未收录坐标"是技术词，
  家长会读成"这个学校不存在"。
- 地图只画**已收录坐标**的学校；放不上的走 ④ 的名单，并在图下计数，**不允许让总数对不上**。
- **登记一条已知风险（评审 S5，本期不改）**：⑥「已录入的孩子」的**兴趣列是自由文本**，
  逐行铺在公开大屏上。它没有姓名，但自由文本里可能出现学校、班级、老师等可识别信息
  （例："在 XX 中学打篮球"）——这正是第五节禁止的那个组合的一半。
  本期按原方案标为"不变"，**登记在此**：一期在大屏上把该列收起（或只留"画像状态"），
  详情留给 `/child/[token]`；与 `AGENTS.md` 第九节第 6 条（`/api/children/summary` 未脱敏）同一类缺口。

### 3.4 现场态：一页"活的"大屏（**v1.1 新增，评审 M1 / S2**）

**这一页现在的实现是"快照"**：只在打开时拉一次数据，之后要人点「刷新数据」。
活动当天的真实节奏是家长陆续填、工作人员在忙、大屏一直开着——**没有人会想到去点刷新**，
于是"现场全景"报的是打开那一刻的数字，而且它看起来完全正常，只是旧的。

**要求：**

1. **自动刷新**：每 30–60 秒拉一次 `/api/children/summary`（沿用已有的 `cache: "no-store"` 与 15s 超时）；
2. **不打扰正在发生的动作**：AI 分析进行中、弹窗打开、删除进行中时**跳过这一轮**；
3. **失败静默降级**：后台刷新失败**不清空数据、不弹红字**，保留最后一次成功的数据；
   连续失败 3 次才在标题行显示一行小字「数据可能已过期 · 最后更新 HH:MM」；
4. **"更新于 HH:MM"**（见 §3.1 的 ①）：每轮成功就更新，**现场工作人员一眼就能判断大屏是不是活的**；
5. **不许让人看见它在刷新**：后台那一轮**不能**翻转按钮的"读取中…"状态、不能禁用工作人员按钮
   ——否则大屏每 60 秒闪一次，现场会以为页面在抽风；
6. **可证伪的验收**：插一条新记录 → **不碰任何按钮** → 60 秒内大屏的总数 +1。

**空态（把 `docs/11` §4.4 的要求提到产品层）**：活动开始前大屏就会打开，那时一条数据都没有。
空态要写清"**正在收集**"（不是空白、不是"暂无数据"），底图照常画，不白屏。

**开屏前 3 件事（写进现场值班清单，`docs/09` §10 里给可勾选的一条）**：

1. 点一次「AI 补全分类」，直到提示消失（否则 8 类统计会缺一块）；
2. 看一眼地图上有没有点——没有点先确认是不是**还没人填**，而不是去查代码；
3. 看一眼「更新于」的时间在不在跳。

### 3.5 第一屏容量：目标要求"往哪走"也在第一屏（**v1.1 新增，评审 M5**）

§1 立的目标是"大屏头三秒要回答『今天现场有多少人、**往哪走**』"，
但按现在的版面，1080p 全屏时 **8 类条形图整体落在折线以下**（地图 `58vh` = 626px，
地图底部已在 y≈916，方向统计的标题在 y≈1030）。"有多少人"看得到，"往哪走"要滚。

**要求**（两选一，建议 A）：

- **A（建议）**：地图高度 `58vh` → `min(52vh, 520px)`（1080p 下 520px，4K 下不失控），
  并在标题行右侧加一条紧凑的「人数最多的 3 个方向」（3 个短标签 + 人数，不做条形）；
- **B**：把方向统计整块提到地图之前（代价：丢掉"打开就是一张地图"的视觉冲击）。

**验收**：在 **1920 真机**上确认"人数最多的 3 个方向"与"已录入孩子数"同屏可见
（这条本来就在 `docs/09` §10.2 第 14 条"没做"的清单里）。

### 3.6 方向统计的呈现（**v1.1 新增，评审 S1**）

第二块给出"12 人往数学与计算走"，然后就没有下一句了——而产品的核心链条是
「兴趣特质 → 成长方向 → **方向在世界上通向哪里** → 地图」。`/colleges` 不按方向筛院校
（数据里没有院校-方向映射，这是对的），所以**链条在这一屏确实是断的**。

**要求**：给 8 类各配**一行静态的类目释义**，渲染在类目名与人数下方，例如
`例如：数学 / 统计 / 数据科学 / 计算机 / 人工智能`。

- 8 行人工维护的文案，**不需要 AI、不需要建库**，不违反"一期不建院校-专业库"
  （它是**类目释义**，不是推荐）；
- 文案前带"例如"两个字，避免被读成专业目录；
- 与 `docs/11` §4.3 的"0 人不渲染"一致：没人的类别连释义一起不渲染。

### 3.7 场次：一天一场（**v1.2 新增**）

**背景（这是个缺口，不是 bug）**：`/api/children/summary` 是全表累计、没有日期过滤，
所以大屏只有两个状态——**全部** 和 **没有**（点「清空孩子数据」）。中间那档"今天这一场"是缺的，
于是现场只能靠**不可逆的清空**来分段。

**实测澄清的两件事**（避免按错误的前提做设计）：

- 新记录**不会覆盖**旧记录：`/api/children` 是 `insert ... onConflictDoNothing(submissionKey)`，
  每次提交都是新的一行；`submissionKey` 只防同一次提交重复写。所以「第二天显示完全不同的 15 所」
  **不会发生**——现状是大屏把两天的学校**累加**（同校合并）。
- `children` 表里有 `created_at`、**没有**场次字段。因此按天分场次**不需要数据库迁移**。

**决策（2026-09-17 拍板）**：

| 项 | 规则 |
| --- | --- |
| 场次粒度 | **一天一场**，按**北京时间**的自然日 |
| 大屏默认 | 显示**今天这一场**；孩子方向统计与梦想院校统计**都以本场为分母** |
| 切换 | 工作人员可切到此前**有数据**的日期，或「全部场次」（浅色小控件，不抢第一屏） |
| 时间边界 | 一律按北京时间算日界。**不能用数据库的 `current_date`** —— 托管库通常是 UTC，早上 7 点的活动会被算成前一天 |
| 历史回看 | **不上大屏**。大屏是公开页面，"英文名 + 画像"正是 `AGENTS.md` 第五节禁止的组合；历史数据回看放工作人员侧（首页，或将来 `/entry` 的口令后） |

**明确不做**：

- **不做「任务模块」** —— 任务是有状态、有负责人、有进度的项目管理概念；这里的真实需求只是**给记录分组**；
- **不做一天多场**（已确认一天一场）。将来真要加，给 `children` 加一列 `session` 即可，加列不影响已有数据；
- 不改「清空孩子数据」的语义（它仍然清全部）。把它挪回首页是 `docs/11` M6 第 ⑥ 项，待做。

**影响面**（全站只有大屏在用这两个接口，改起来干净）：`/api/children/summary`（过滤 + 返回场次信息）、
`/api/children/wordcloud`（同一场，否则词云会把历史混进来）、`/explore`（场次条 + 切换器）。
技术细节见 `docs/11` 七、M7。

### 4.2 三个必须处理的坑

1. **`MAIN=1` 必须过滤**，否则同一所学校会按校区重复打点
   （例：`Pratt Institute-Main` 与 `Pratt Manhattan-A Division of Pratt Institute` 是两条记录）。
   4 年制 + 主校区 = **2480 所**，其中 12 所（`Pensacola Christian College`、
   `University of Fairfax` 这类小型宗教院校）在源数据里的 `LATITUDE` / `LONGITUDE`
   写的是 `NA`，**可用坐标 2468 所**——提取脚本丢掉这 12 条，产物就是 2468 行。
2. **「大学下辖的学院」在官方目录里不是独立机构**。帕森斯（Parsons）属于 The New School，
   The New School 的坐标就是帕森斯所在地（66 W 12th St, NYC），**作为地图打点是正确的**，
   但名字对不上 → 需要一条人工覆盖。
3. **中文名和官方英文名对不上**。数据源只有英文名；中文名要靠我们自己维护的别名表
   （`lib/university-names.ts`，现 69 条）做桥。这决定了「中文输入的覆盖率 = 别名表的覆盖率」。

### 4.3 匹配管线（三级 + 唯一性闸）

| 级 | 规则 |
| --- | --- |
| ⓪ | `parseUniversities()` 拆词 + 查别名表 → 规范中文名（沿用现有函数，不改口径） |
| ① | **别名表**：每个规范名带着它的英文别名数组，逐个查坐标索引 |
| ② | **精确匹配**：规范化后与机构名（`INSTNM` 及其变体）完全相同 |
| ③ | **唯一包含匹配**：输入名 ⊂ 机构名，或机构名 ⊂ 输入名，且**只命中一所**才接受 |
| ④ | **人工覆盖**：`data/university-coords.overrides.json`（当前只需 1 条：帕森斯 → The New School） |
| — | 都没有 → 标记「**暂未收录**」（v1.1 改文案，见 §3.3），进 ④ 的名单，并在图下计数 |

规范化在 `lib/university-names.ts` 已有的 `key()`（NFKC + 去空格标点）之上，**再多一步：
去掉结尾的主校区后缀——`main campus` 与 `main` 两种都要去**（源数据里两种写法都有：
`Pratt Institute-Main`、`Georgia Institute of Technology-Main Campus`），
否则佐治亚理工、宾州州立、普渡、俄亥俄州立这一批会全部落空。除此以外不加任何规则
（不去 `The` 前缀、不去 `University` 后缀、不做缩写扩展）——那些会误合并
（`Boston University` 与 `Boston College` 是两所学校），细节见 `docs/11` §3.3。

③ 的**唯一性闸**是关键：不设闸的话 `University of Washington` 会同时命中
`-Bothell`、`-Tacoma`、`-Seattle` 三条，把点打错地方。
（实测：主校区在源数据里叫 `University of Washington-Seattle Campus`，走的是**唯一包含**，
不是精确匹配——`via` 仍是 `alias`。）

### 4.3.1 中文校名的两个来源必须对齐（**v1.1 新增，评审 M6**）

坐标表里只有**英文**机构名。家长填中文时，**能不能上地图完全取决于别名表**——
`docs/10` v1.0 §4.2 坑 3 已经写出这个机制，但当时把它降级成了"活动后补"。
**v1.1 实测后改口径**：这不只是"以后更好"，而是**当天就看得见的缺口**。

| 输入写法 | 可命中的院校数 | 依据 |
| --- | --- | --- |
| 英文机构名（`Syracuse University`） | **2468** | 坐标表原文精确 / 唯一包含 |
| 中文，且在别名表里（`斯坦福大学`） | **69** | `src/lib/university-names.ts` |
| 中文，取自**我们自己 `data/colleges.csv` 的 113 个中文校名** | **56 / 113** | 逐条跑 `locateSchool()` |

命不中的 57 个全都出现在**我们自己的页面上**（`/colleges` 选校地图展示的就是这些中文名），
其中一部分只是"一字之差"的译名不一致：

| 我们在 `data/colleges.csv` 上展示的 | 别名表里的规范名 | 结果 |
| --- | --- | --- |
| 卡**耐**基梅隆大学 | 卡**内**基梅隆大学 | 命不中 |
| 伊利诺伊大学**厄本那**-香槟分校 | 伊利诺伊大学**厄巴纳**-香槟分校 | 命不中 |

**要求（活动前做完，三件）**

1. **对齐两个来源**：`data/colleges.csv` 的 113 个中文名必须**全部**能被 `locateSchool()` 命中
   （补进别名表，或按译名差异逐条对齐）；
2. **同时收下常见的英文写法**（`Syracuse` / `Syracuse University`），英文路径本来就覆盖 2468 所；
3. **把结果写成单测**：`113/113 命中`（现在是 **56/113**），与已有的「69/69 命中」并列——
   以后谁改别名表，掉一条就红。

> **为什么不能等活动后**：家长会从我们自己的页面上抄中文校名（`/colleges` 是全站唯一展示
> 院校中文名的页面）。活动当天没有补表的时间，而 `docs/10` §8 立的指标是"地图命中率 ≥ 85%"。

### 4.4 产物放哪一层：**服务端**，不进浏览器

| 选项 | 结论 |
| --- | --- |
| 客户端（像 `colleges-data.ts` 那样进 bundle） | ❌ 2468 行 ≈ 190KB 源码，白占大屏首屏 |
| **服务端（本方案）** | ✅ 匹配在 `/api/children/summary` 里做完，只把下面这组字段返回给浏览器 |

```ts
dreamSchools: { name, count, matched, st, lat, lng }[]   // 未命中的也返回，matched:false、坐标为 null
```

做法：`scripts/extract-university-coords.ts`（一次性，从 Scorecard 抽出 CSV）→
`scripts/build-coords.ts`（读 `data/university-coords.csv` 写 `src/lib/university-coords.ts`，
紧凑数组，**提交进仓库**）。

**为什么产物必须提交**：Docker 构建上下文是 `src/`（`compose.yaml` 的 `build: .`），
`data/` 不在镜像里，`next build` 也不跑 `build:data` —— 跟 `colleges-data.ts` 是同一套逻辑。

数据分三层，职责不重叠：

| 表 | 内容 | 谁用 |
| --- | --- | --- |
| `data/colleges.csv` → `lib/colleges-data.ts` | 113 所 × 46 列**事实字段**（录取率、批次、文书…） | 选校地图 |
| `data/university-coords.csv` → `lib/university-coords.ts` | 2468 所，**只有名字与坐标** | 现场全景的梦想院校地图 |
| `lib/university-names.ts` | 中英文别名（人工维护） | 两处共用 |

**优先级（v1.1 作废）**：原文写「同一个学校两边都有时以 113 表为准」。
实测后**这条规则作废**：同一所学校在两份表里的坐标差，投影后是
Stanford **0.057px**、Harvard **0.062px**、MIT **0.022px**、Princeton **0.156px**
（`tmp/probe-project.ts`，脚本不进版本库）——全都小于肉眼与回归基准的量级，
不需要"优先"，也不需要为此把 113 表引到服务端。`docs/11` §1.2 同步更正。

### 4.5 验证（可证伪）

| 断言 | 怎么证伪 |
| --- | --- |
| 别名表里**每一个**规范名都能定位到坐标 | 遍历 69 条，命中数必须 = 69 —— **已达成 69/69**（v1.1 复测；为哥伦比亚大学补了官方英文名） |
