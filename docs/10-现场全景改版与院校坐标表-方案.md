## 二、方向分类：4 类 → 8 类

### 2.1 最终定义（单轴：学科领域）

| # | 类别 | 覆盖 | 与旧 4 类的关系 |
| --- | --- | --- | --- |
| 1 | 人文科学 | 文学 / 历史 / 哲学 / 语言学 / 宗教 / 古典学 / 区域研究（人文向） | 保留（旧：人文科学） |
| 2 | 社会科学 | 政治 / 社会学 / 心理 / 人类学 / 国际关系 / 公共政策 / 法律预科 | 保留（旧：社会科学） |
| 3 | **商科与管理** | 经济与金融 / 管理 / 创业 / 市场 / 会计 / 信息系统（商科向） | **拆分自旧「社会科学」** |
| 4 | 自然科学 | 物理 / 化学 / 生物 / 地球与海洋 / 天文 / 环境科学 | 保留（旧：自然科学） |
| 5 | **数学与计算** | 数学 / 统计 / 数据科学 / 计算机 / 人工智能 / 信息科学 | **拆分自旧「自然科学」** |
| 6 | **工程与应用** | 机械 / 电子 / 土木 / 材料 / 生物医学工程 / 航空航天 / 建筑 | **拆分自旧「自然科学」** |
| 7 | 艺术与设计 | 视觉艺术 / 音乐 / 表演 / 影视 / 设计（含工业、交互） | 保留（旧：艺术，加「与设计」） |
| 8 | **健康与公共服务** | 护理 / 公共卫生 / 运动科学 / 教育 / 社会工作 / 传媒 | **拆分自旧「自然科学」与「社会科学」** |

**刻意不设的两个桶**（与产品决策一起记在这里，避免以后又绕回来）：

- **「跨学科」不做桶**。它是一个「结构属性」，不是一个学科：认知科学既跨学科、又属于自然或社科。让 AI 在两者之间二选一，同一个方向会在不同批次落到不同的桶，**统计不可复现** —— 家长看到隔壁孩子的「认知科学」归了社科、自己的归了跨学科，这屏数字就失去信任。而「跨学科」这件事方向名自己会说出来（认知科学、神经科学、环境研究、媒体艺术与技术都是 AI 起的方向名）。
- **「职业」不做桶**。中文语境里「职业」贴着「职校 / 职业教育」，在大屏上属于**可能被读成降级**的标签；而它想覆盖的那批专业（商科、护理、教育、传媒）本来都有明确的学科归属，分别落进第 3 / 8 / 7 类，不需要单列。

### 2.2 判定规则（写进 prompt，不得留白）

| 方向语义 | 归入 |
| --- | --- |
| 工程、电子、机械、材料、航空航天、建筑 | 工程与应用 |
| 纯数学、统计、数据科学、计算机、人工智能 | 数学与计算 |
| 偏实现与系统的计算方向 | 工程与应用 |
| 商科、金融、管理、市场营销、会计 | 商科与管理 |
| 护理、公共卫生、运动科学、教育、社会工作、传媒 | 健康与公共服务 |
| 设计（含工业设计、交互设计） | 艺术与设计 |
| 认知科学、神经科学、环境研究这类跨领域项目 | 按其**主要学科归属**，不设「跨学科」桶 |

### 2.3 老数据怎么办

`categorized()` 保持**严格**：类别必须在新 8 类里。于是：

- 库里已经分析过、类别还是旧 4 类的记录，会被判为「待分类」；
- 现场全景页上已有「AI 补全分类」按钮（`pendingCategories`），点一次就按新类重跑 —— 已有链路，不需要新写代码；
- `/api/children/analyze` 在发现记录有 3 个方向但类别不合法时，会走「只重分类、不重生成方向」的分支，成本很低。

> **现在改代价最低**：库里还没有正式数据。等活动当天再改，就是几十条记录重跑 + 现场等着。

### 3.2 地图做什么 / 不做什么

| 做 | 不做 |
| --- | --- |
| 复用选校地图的**底图三层**（海洋 / 邻国陆地 / 美国本土 + AK/HI 插图 + 投影阴影） | 不做缩放、平移、双击 |
| 圆点大小按人次分档，颜色统一 | 不做筛选、搜索、洞察榜 |
| 人次前 8–10 名在地图上挂校名 + 人次 | 不做对比位、不做详情栏 |
| 悬停看「校名 · N 人」（SVG `<title>`，零 JS） | 不做表格视图 |

底图的三个可复用件已经在 `lib/us-map-paths.ts`（`STATE_PATHS` / `NEIGHBOR_LAND` / `US_INSETS`）。
**要抽出共享组件**：把三层底图从 `components/colleges/colleges-map.tsx` 抽成
`components/map/us-base-layers.tsx`，选校地图与现场全景都用它，避免两处各画一套。
投影函数 `project()` 从 `lib/colleges-project.ts` 抽到 `lib/map-project.ts`
（原文件 re-export，所有现有 import 与测试不受影响）。

### 3.3 口径与隐私（**不可妥协**）

- 地图只显示**人次**：`斯坦福 3 人`，**不显示任何姓名**。
  大屏是公开页面，`AGENTS.md` 第五节明令不得出现「孩子姓名 + 个人画像」的组合；
  「谁选了哪所学校」正是那个组合（这也是 `/api/children/summary` 未脱敏那条已知缺口的同类风险）。
- 地图只画**已收录坐标**的学校；放不上的走 ④ 的名单，并在图下写明
  「另有 N 所 / N 人次未收录坐标」，**不允许让总数对不上**。

| 数据源 | **College Scorecard**（美国教育部）`Most-Recent-Cohorts-Institution` |

### 4.2 三个必须处理的坑

1. **`MAIN=1` 必须过滤**，否则同一所学校会按校区重复打点
   （例：`Pratt Institute-Main` 与 `Pratt Manhattan-A Division of Pratt Institute` 是两条记录）。
   4 年制 + 主校区 = **2480 所**，全部有坐标。
2. **「大学下辖的学院」在官方目录里不是独立机构**。帕森斯（Parsons）属于 The New School，
   The New School 的坐标就是帕森斯所在地（66 W 12th St, NYC），**作为地图打点是正确的**，
   但名字对不上 → 需要一条人工覆盖。
3. **中文名和官方英文名对不上**。数据源只有英文名；中文名要靠我们自己维护的别名表
   （`lib/university-names.ts`，现 69 条）做桥。这决定了「中文输入的覆盖率 = 别名表的覆盖率」。

### 4.3 匹配管线（三级 + 唯一性闸）

| 级 | 规则 |
| --- | --- |
| ⓪ | `parseUniversities()` 拆词 + 查别名表 → 规范中文名（沿用现有函数，不改口径） |
| ① | **别名表**：每个规范名带着它的英文别名数组，逐个查坐标索引 |
| ② | **精确匹配**：规范化后与机构名（`INSTNM` 及其变体）完全相同 |
| ③ | **唯一包含匹配**：输入名 ⊂ 机构名，或机构名 ⊂ 输入名，且**只命中一所**才接受 |
| ④ | **人工覆盖**：`data/university-coords.overrides.json`（当前只需 1 条：帕森斯 → The New School） |
| — | 都没有 → 标记「未收录坐标」，进 ④ 的名单，并在图下计数 |

规范化沿用 `lib/university-names.ts` 里已有的 `key()`（NFKC + 去空格标点），保证两处口径一致。
③ 的**唯一性闸**是关键：不设闸的话 `University of Washington` 会同时命中
`-Bothell`、`-Tacoma`、`-Seattle` 三条，把点打错地方。

### 4.4 产物放哪一层：**服务端**，不进浏览器

| 选项 | 结论 |
| --- | --- |
| 客户端（像 `colleges-data.ts` 那样进 bundle） | ❌ 2480 行 ≈ 190KB 源码，白占大屏首屏 |
| **服务端（本方案）** | ✅ 匹配在 `/api/children/summary` 里做完，只把 `{name, count, lat, lng}` 返回给浏览器 |

做法：`scripts/build-university-coords.ts` 读 `data/university-coords.csv`，写
`src/lib/university-coords.ts`（紧凑数组，**提交进仓库**）。

**为什么产物必须提交**：Docker 构建上下文是 `src/`（`compose.yaml` 的 `build: .`），
`data/` 不在镜像里，`next build` 也不跑 `build:data` —— 跟 `colleges-data.ts` 是同一套逻辑。

数据分三层，职责不重叠：

| 表 | 内容 | 谁用 |
| --- | --- | --- |
| `data/colleges.csv` → `lib/colleges-data.ts` | 113 所 × 46 列**事实字段**（录取率、批次、文书…） | 选校地图 |
| `data/university-coords.csv` → `lib/university-coords.ts` | 2480 所，**只有名字与坐标** | 现场全景的梦想院校地图 |
| `lib/university-names.ts` | 中英文别名（人工维护） | 两处共用 |

**优先级**：同一个学校两边都有时，**以 113 表为准**（它的坐标有 0.07px 的回归基准守着）。

### 4.5 验证（可证伪）

| 断言 | 怎么证伪 |
| --- | --- |
| 别名表里**每一个**规范名都能定位到坐标 | 遍历 69 条，命中数必须 = 69（现在是 59） |
| 坐标投影后落在画布内（0..975 / 0..610） | 逐条 `project(lat,lng)` 断言，越界即失败 |
| 主校区去重 | `Pratt Institute-Main` 与 `Pratt Manhattan…` 不能同时进索引 |
| 唯一性闸真的在起作用 | 用 `University of Washington` 断言不误命中分校 |
| 产物可重建 | `pnpm build:coords` 重跑后 `git diff` 干净 |
| 数据源可追溯 | `data/university-coords.csv` 头部写来源 URL + 版本日期 |

## 七、待确认

1. **要不要并别的公开源**：Wikidata / IPEDS 本机拉不通（`nces.ed.gov` 连不上、`query.wikidata.org` 超时），Scorecard 一个源已够用，**建议只用 Scorecard**。
2. **别名表要不要这轮就扩**：建议不扩。没有可靠的中文名来源，硬编等于编数据；等活动后用真实未命中名单来补。
3. **`/api/children/summary` 脱敏**：这次**不动**（沿用一期决定）。地图只显示人次，不显示姓名。
